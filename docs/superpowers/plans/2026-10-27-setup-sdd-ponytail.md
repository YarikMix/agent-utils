# Настройка SDD + Ponytail — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить в `YarikMix/agent-utils` скилл настройки глобальных инструкций совместной работы Superpowers SDD и Ponytail для Claude Code и Codex, с необязательным PAIW.

**Architecture:** Один скилл использует существующую подключённую память, иначе добавляет компактный блок в действующие глобальные инструкции. Плагин содержит только инструкции; оба клиента получают один и тот же скилл через штатные manifests и marketplace. Проверки наблюдают изменения изолированных файлов, не затрагивая настоящую память пользователя.

**Tech Stack:** Agent Skills Markdown, JSON manifests, существующие CLI клиентов; Python 3 standard library для разовых проверок артефактов. Новых зависимостей нет.

**Spec:** `docs/superpowers/specs/2026-10-27-setup-sdd-ponytail-design.md`

## Global Constraints

- Имена плагина и скилла: `setup-sdd-ponytail`; начальная версия упаковки — `1.0.0` (решение плана).
- «PAIW поддерживается, но не является зависимостью».
- «Не менять настройки второго клиента лишь потому, что он установлен»; по умолчанию целевой клиент — текущий.
- Использовать существующую подключённую глобальную память, иначе штатные глобальные инструкции; наличие каталога не доказывает подключение.
- Сохранять полный базовый абзац из раздела «Содержимое правила» спецификации дословно; включить оба указания о передаче и приёмке.
- «Запрос настройки разрешает необходимые изменения в своей области без повторного согласования»; проверка/объяснение не разрешают запись.
- Сохранять чужой текст, формат и ссылки; полная настройка — без изменений, частичная — дополнение на месте, повторный запуск — без дублей.
- «Не создавать override ради этой настройки»; управляемые и недоступные источники не обходить затеняющими файлами.
- «Не изменять исходники, кэш или шаблоны Ponytail и Superpowers»; не устанавливать отсутствующие плагины.
- Не добавлять установщик, хуки, зависимости, автозапуск настройки или ограничение обнаружимости только явным вызовом.
- Наличие записи, загрузка в новом клиенте и наблюдаемое выполнение SDD — три разных результата.
- В публичных артефактах нет личных путей, приватных конфигов, raw-логов пользователя и секретов; общий абзац правила разрешён к поставке.

## Review Focus

| Условие | Ожидаемое поведение | Проверка задачи 1 |
|---|---|---|
| Непустой/пустой override и нестандартный Codex home | Запись только в реально действующий глобальный файл | `codex-effective-file` |
| Каталог PAIW существует, но не подключён, либо память только проектная | Не использовать их вместо глобальных инструкций | `memory-scope` |
| Полная/частичная запись, повторный запуск | Сохранить соседний текст, дополнить на месте, затем нулевой diff | `memory-update` |
| Симлинк на управляемый источник или конфликт пользовательских правил | Сообщить конкретный блокер; не создавать обходной файл и не отменять правила | `protected-or-conflicting-source` |
| Только проверка, второй клиент установлен, плагины не подтверждены | Без лишних записей/установок; точный отчёт о границах результата | `request-scope` |

**Interfaces:**

- Produces: один скилл с frontmatter `name: setup-sdd-ponytail`; описание `Use when…` о запросе настройки/проверки интеграции, не об обычном выполнении SDD. Задача 2 упаковывает каталог `skills/` без изменения поведения.

- [ ] **Шаг 1: Зафиксировать сценарии и эталоны до написания скилла.** В отчёте записать вход, запрос и ожидаемые изменения. Создать в приватном временном каталоге синтетические профили с сохранёнными исходными снимками и маркерами соседнего текста. Конкретные имена, содержимое соседних инструкций и раскладки отложенных профилей не переносить примерами в скилл.

| Имя теста | Вход | Проверяемый результат |
|---|---|---|
| `codex-effective-file` | Нестандартный каталог профиля; `AGENTS.md` и непустой `AGENTS.override.md`; второй вариант — пустой override | В первом случае меняется только override; во втором только `AGENTS.md`; стандартный профиль не меняется |
| `claude-native` | Claude Code без PAIW, пользовательский `CLAUDE.md` отсутствует либо содержит чужой раздел; отдельный вариант с нестандартным каталогом конфигурации | Создан/дополнен правильный пользовательский файл; чужой раздел сохранён; папки PAIW не созданы |
| `memory-scope` | Один профиль со ссылкой на глобальный индекс; другой с неподключённым каталогом PAIW и проектной памятью | В первом заметка и одна ссылка в индексе; во втором блок в глобальных инструкциях, проектная память нетронута |
| `memory-update` | Подключённая заметка с базовым абзацем без передачи субагентам, затем повтор настройки и отдельная полная запись | Частичная дополнена на месте; базовый абзац дословен; ссылка одна; повтор и полная запись дают нулевой diff |
| `protected-or-conflicting-source` | Симлинк на обозначенный управляемый файл; другой профиль с явным противоположным пользовательским правилом | Без записи и создания fallback/override; конкретное ограничение либо вопрос о конфликте |
| `request-scope` | «Только проверь» при неполной записи; настройка текущего клиента при наличии второго; отсутствие подтверждения плагинов | Проверка — нулевой diff; настройка — только целевой клиент; плагины не устанавливаются; отчёт не заявляет активную совместимость |

Для каждого профиля сравнивать множество созданных/изменённых путей с эталоном, сохранность соседних байтов и отсутствие дублей. Для записи правила извлекать базовый абзац из спецификации и проверять его точное присутствие, а не только ключевые слова. Отчёт должен перечислить оба указания: передачу во все задания исправлений и приёмку по доказательствам в существующем цикле SDD.
