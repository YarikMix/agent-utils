# Figma Design Workflows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Расширить figma-ops маршрутами создания и исправления экранов, сохранив удобное чтение и комментирование без edit-доступа.

**Architecture:** Короткий dispatcher в SKILL.md выбирает чтение, комментарии, исправление или создание по поручению пользователя. Один новый reference связывает существующие проверки, Refero и официальный Figma MCP; runtime CLI не меняется.

**Tech Stack:** Markdown skills/references, JSON manifests/catalogs, Python unittest для упаковки; синтетические агентные сценарии по writing-skills.

**Spec:** [Утверждённая спецификация](../specs/2026-11-04-figma-design-workflows-design.md).

## Global Constraints

- Два новых маршрута внутри существующего figma-ops; никаких новых CLI-команд или MCP-серверов.
- Чтение и реализация UI в коде не разрешают изменения в Figma; комментарии имеют отдельные права и поручения.
- Корпоративный Mac с Dev Mode и возможностью комментировать не должен требовать edit seat, write-проб, копирования в Drafts или новых MCP.
- По задаче загружаются только нужные references. Для read-only use_figma обязательный figma-use всё равно нужен.
- Запись дизайна — официальный use_figma; его текущие prerequisites и schemas не дублируются. Новые экраны используют Refero и дизайн-систему продукта.
- Механическое исполнение согласованной правки опирается на существующий макет и не начинает новый поиск стиля.
- Проверяются все затронутые варианты, свежий рендер экрана и читаемые детали; прототип проверяется, когда он заказан.
- Комментарии отправляются/закрываются в пределах поручения; существующее разрешение не запрашивается повторно.
- Рабочая версия плагина: 1.6.0 в обоих manifests и обоих каталогах. Кэш установленного плагина не редактируется.
- До реализации пользователь выбирает способ исполнения этого плана; предыдущий выбор для другой задачи не переносится.

## Review Focus

1. Dev Mode + наличие write-tools: агент не принимает доступность инструмента за разрешение на запись (сценарий C, задача 1).
2. Общий компонент с переопределениями и разными ширинами: один удачный скриншот не закрывает все варианты (A, задача 1).
3. Уменьшенный screenshot: увеличение maxDimension не доказывает достаточное разрешение или 2× (D, задача 1).
4. Ответ/Resolve с неясным исходом или неполный тред: проверка по root ID без слепого повтора и ложного успеха (E, задача 1).
5. Нет Refero MCP или запрещена запись: не выдумывать исследования, не обходить запрет другим транспортом; продолжить доступную часть (B/F, задача 1).
