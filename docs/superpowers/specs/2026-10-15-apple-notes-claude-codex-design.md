# Apple Notes для Claude Code и Codex в agent-utils

Дата: 2026-10-15. Статус: дизайн согласован в диалоге; письменная спека ожидает ревью.

## Цель и согласованные требования

Пользователь устанавливает `apple-notes-folder` из собственного Git-маркетплейса
в Claude Code или Codex и работает с Apple Notes только в одной выбранной папке.
Оба клиента используют один MCP-сервер и общую реализацию операций с заметками.
Упаковка, настройка и интеграция с диалогом учитывают особенности клиента.

Согласовано:

- Репозиторий называется `YarikMix/agent-utils`. Переименование на GitHub уже
  выполнено и проверено через API. Обновление файлов репозитория ещё предстоит.
- Папка настраивается независимо в каждом клиенте. Изменение настройки Codex
  не меняет настройку Claude и наоборот.
- Картинки принимаются только из вложений пользовательских сообщений текущего
  диалога. Произвольный файл на диске не становится допустимым по своему пути.
- При неизвестном происхождении картинки операция с этой картинкой отклоняется.
- Сохраняются ограничения папки, вложений, списков и защищённых заметок.
- Проверяется установка через маркетплейс, а не только запуск `dist/server.js`.

Успех — воспроизводимая установка и работа в обоих локальных клиентах, включая
успешную вставку пользовательской картинки и отказ файлу, которого нет во
вложениях текущего диалога. Одни отказы без успешной вставки не являются приёмкой.

## Основание и состояние проекта

База: `main`, коммит `eed751aca38991ab547a314a4401ce84fe54e0cf`,
плагин версии `1.1.0`. Исходные решения описаны в
[предыдущей спеке](2026-09-27-apple-notes-folder-design.md).

Сейчас плагин содержит собранный stdio MCP-сервер, семь инструментов `notes_*`,
Claude-манифест с `userConfig.folder`, хук `PreToolUse` на `Bash|Monitor` и проверку
картинок по принадлежности временному каталогу Claude. Подсказки настройки
привязаны к `/plugin configure`.

На машине при проектировании доступны Codex CLI `0.162.1` и Claude Code
`2.1.300`. Это целевые версии первичной приёмки, а не утверждение, что новая
интеграция уже проверена. Новые версии объявляются поддерживаемыми после
проверки адаптера, вложений и хука.

### Сознательные изменения прежних решений

| Было и почему | Станет и почему |
|---|---|
| Корень картинок `/private/tmp/claude-<uid>/`: там лежат вставленные картинки и scratchpad | Допуск по вложениям конкретного диалога: пользователь отдельно выбрал «только из вложений», поэтому принадлежности каталогу недостаточно |
| Папка и подсказки настройки только из Claude `userConfig` | Claude сохраняет свой процесс; Codex получает независимую настройку и собственные подсказки |
| Публичные инструкции используют `YarikMix/claude-plugins` | Действующие инструкции используют `YarikMix/agent-utils` по явной просьбе пользователя |
| Единственная упаковка для Claude Code | Один сервер и отдельные манифесты и адаптеры двух клиентов |

Остальные решения исходной спеки сохраняются. В частности, отказ от прямого
чтения базы Apple Notes и запрет изменения заметок со списками или вложениями
не отменяются ради совместимости с Codex.

## Границы работы

В рамках этой задачи поддержка Codex добавляется к Apple Notes. Плагины
`selectel-ops` и `typescript-native-lsp` сохраняются в каталоге Claude; ссылки
установки в их действующей документации обновляются после переименования.
Их перенос в Codex не входит в эту спеку. Исторические спеки и планы не
переписываются ради замены старого имени репозитория.

Поддерживаются локальные потоки выполнения на macOS с Apple Notes и Node.js
не ниже 20. Удалённое выполнение без доступа к локальным Заметкам, облачная
оркестрация, Windows и публичный каталог OpenAI не входят в приёмку.
Для других локальных интерфейсов Codex нельзя заявлять поддержку только на
основании того, что они используют тот же app-server: необходима проверка
передачи вложений и запуска плагина в соответствующем интерфейсе.

## Архитектура и упаковка

### Общая часть

Общий сервер отвечает за поиск выбранной папки, проверку принадлежности заметки,
операции, Markdown, ограничения вложений и списков, ошибки и проверку картинки.
Хост выбирается явно при запуске (`claude` или `codex`), без угадывания по
случайно унаследованным переменным окружения.

Адаптер хоста отвечает за источник настройки, текст помощи, получение контекста
вызова и подтверждение пользовательских вложений. Он не реализует операции
Apple Notes и не может ослабить проверки общей части.

### Каталоги

- Сохранить `.claude-plugin/marketplace.json`, его идентификатор
  `yarikmix-plugins` и действующие имена плагинов.
- Добавить `.agents/plugins/marketplace.json` с отдельной записью Apple Notes
  для Codex. Имя каталога — также `yarikmix-plugins`; клиенты хранят установки
  отдельно. Запись содержит source, category и обязательные policy-поля.
- В `plugins/apple-notes-folder/` сохранить `.claude-plugin/plugin.json`;
  добавить `.codex-plugin/plugin.json` и корневой `.mcp.json` для Codex.
  Использовать документированный совместимый формат Codex, чтобы не менять
  работающий `userConfig` Claude ради миграции на переносимый root-манифест.
- Codex-манифест явно ссылается на свои MCP, setup-скилл и hook-конфигурацию.
  Claude-манифест явно ссылается на свою hook-конфигурацию. Автообнаружение
  `hooks/hooks.json` не должно подключать конфигурацию другого клиента.
- `dist/` остаётся закоммиченным и самодостаточным: установка не требует
  `npm install`, сборки или скачивания зависимостей.
- В обоих каталогах версия Apple Notes — `2.0.0`: допуск изображений становится
  строже и перестаёт принимать scratchpad только по его расположению.

Компоненты реализации располагаются внутри существующего плагина: общий сервер,
адаптеры хостов, помощник настройки, подтверждение вложений, конфигурации хуков,
setup-скилл, тесты. Сборка включает необходимые исполняемые точки входа.
Дублировать исходники и сборку сервера между клиентами нельзя.

## Настройка папки

### Claude Code

Сохраняются `userConfig.folder`, передача через `NOTES_FOLDER` и
`/plugin configure apple-notes-folder@yarikmix-plugins`. Существующий выбор не
импортируется в Codex и не перезаписывается при установке Codex-плагина.

### Codex

Плагин содержит setup-скилл, который спрашивает точное имя папки и запускает
пакетный помощник настройки с этим явно выбранным значением. Помощник использует
общую проверку папки: непустое имя, запрет «Недавно удалённых», существование и
однозначность среди аккаунтов и подпапок. Для этой проверки читаются метаданные
папок, содержимое заметок не требуется.

Настройка хранится в
`$CODEX_HOME/agent-utils/apple-notes-folder/config.json`, где при отсутствии
`CODEX_HOME` используется `~/.codex`. Файл содержит версию формата `1` и имя
`folder`, не содержит заметок и не зависит от версии установленного пакета.
Каталог закрыт для других пользователей (`0700`), файл — `0600`; обновление
атомарное. Неуспешная проверка оставляет прежний файл без изменений.

MCP-сервер в режиме Codex читает только этот источник, игнорируя случайно
унаследованный `NOTES_FOLDER`. В режиме Claude источник Codex не читается.
Настройка фиксируется при старте MCP; после изменения помощник сообщает о
необходимости перезапуска MCP или начала новой сессии. Уже запущенный сервер
не переключается на другую папку посреди операции.

Пустая, отсутствующая, повреждённая или неизвестной версии настройка даёт
понятную ошибку настройки у инструментов, а не доступ ко всем папкам.
В Codex подсказка ведёт к setup-скиллу; в Claude — к `/plugin configure`.

Общедоступного MCP-инструмента для смены разрешённой папки нет. Setup-скилл не
выбирает папку по собственному предположению, тексту заметки или инструкции
внутри вложения. В конфиг Codex и настройки других MCP установка вручную
новую серверную запись не добавляет: подключение принадлежит плагину.

## Картинки только из пользовательских вложений

### Контракт происхождения

Допустима картинка, содержащаяся в структурированном вложении пользовательского
сообщения текущего диалога. Допускаются вложения предыдущих сообщений этого же
диалога, пока клиент позволяет подтвердить их происхождение и получить байты.
Текст с упоминанием пути к файлу вложением не считается.

Не подходят: файлы рабочего каталога и scratchpad сами по себе, картинки из
других диалогов, результаты `view_image`, скриншоты инструментов, сгенерированные
агентом картинки и ссылки на изображения в интернете. Если пользователь позже
сам прикрепил такой файл, его новое пользовательское вложение подходит.

Адаптер принимает только известную структурированную форму пользовательского
сообщения с вложением. Поиск пути регулярным выражением по тексту всего лога,
сканирование всех сессий и расширение разрешённого корня до `/tmp` запрещены.
При использовании transcript читается только transcript текущего вызова,
переданный клиентом; данные других диалогов не собираются. В записи пользователя
извлекаются лишь метаданные вложений и сами нужные изображения.

Источник байтов — сохранённое содержимое структурированного вложения либо
неизменяемая копия/хеш, зафиксированные интеграцией при получении пользовательского
сообщения. Один `localImage.path` без подтверждения исходных байтов недостаточен:
позднее содержимое файла могло измениться. Сравнение файла с хешем, впервые
вычисленным только перед записью заметки, также не подтверждает исходное вложение.
Если клиент не позволяет восстановить или зафиксировать эти данные, картинка
не получает допуск; успешная интеграция требует решения этой проверки.

### Передача подтверждения общему серверу

У stdio MCP-вызова нет гарантированного поля с текущим диалогом. Поэтому клиентский
`PreToolUse` для трёх пишущих инструментов с Markdown связывает подтверждение
вложений с конкретным вызовом, прежде чем тот попадёт на сервер:

1. Получает session/transcript и идентификатор вызова из события клиента.
2. Находит только пользовательские вложения текущего диалога и сопоставляет
   запрошенные в Markdown картинки с ними.
3. Проверяет изображения и создаёт закрытые копии нужных байтов в runtime-каталоге
   своего клиента. Регистрирует одноразовый допуск для точного имени инструмента,
   хеша его исходных аргументов, идентификаторов диалога и вызова, списка путей и
   хешей изображений. Другие вложения в допуск не включаются.
4. Через поддержанный клиентом `updatedInput` добавляет необязательный служебный
   аргумент `attachment_ticket` к `notes_create`, `notes_append` или `notes_update`.
   Это непрозрачный случайный идентификатор допуска, не произвольный путь.
5. Сервер принимает билет только из runtime-каталога своего хоста, проверяет
   привязку к инструменту и аргументам, срок и однократность, проверяет хеши копий.
   Файлы для Apple Notes берутся из этих копий, а не повторно по исходному пути.

Срок допуска — 15 минут. Просроченный, повторный, неизвестный или не совпадающий
с аргументами билет отклоняется до изменения заметки. Для повторного вызова
клиент создаёт новый допуск. Runtime-каталоги клиентов разделены, имеют права
`0700`, файлы — `0600`, не находятся в обновляемом cache плагина. Снимки картинок
хранятся до 24 часов и очищаются при следующем запуске/обслуживании runtime;
незавершённые операции не очищают их досрочно.

Семь существующих MCP-инструментов сохраняются. Новый служебный аргумент
необязателен для текста; для картинок без действующего подтверждения возвращается
ошибка. Агент не выпускает билеты через отдельный MCP-инструмент и не должен
подбирать или формировать их вручную. Markdown остаётся пользовательским
интерфейсом вставки; общий конвертер получает проверенные пути копий.

Реестр и hook-контекст защищают от случайного использования файлов и смешения
диалогов. Это не граница против намеренного обхода процессом того же пользователя,
который может менять локальные файлы, hook-код и сам плагин.

### Файлы и атомарность отказа

Сохраняются форматы PNG, JPEG, GIF, HEIC и WebP по сигнатуре, лимит 10 МБ на
картинку, запрет символических ссылок вместо файла и проверка реального пути.
Сопоставление с вложением и получение снимка должны исключать подмену исходного
файла между проверкой и копированием. Служебные копии также проверяются перед
передачей Apple Notes.

Все картинки входного Markdown проверяются до записи. Если хотя бы одна
недопустима, не создаётся заметка и не дописывается/заменяется её текст.
Прежние `note-image:N` остаются заглушками чтения, а не разрешениями на вставку.
Сервер не скачивает внешние изображения.

### Проверка совместимости адаптеров

До реализации интеграции зафиксировать обезличенные примеры реальных событий
и структуры пользовательских вложений обеих целевых версий. Должны быть
подтверждены: контекст текущего диалога, источник пользовательского вложения,
доступ к исходным байтам и переписывание аргументов MCP через `updatedInput`.
Документация Codex предупреждает, что формат transcript не является стабильным
интерфейсом. Парсер изолирован в адаптере и имеет тестовые примеры поддержанных
форм, включая отличия кодирования картинок между клиентами.

Эта проверка — обязательная зависимость реализации. Если клиент не предоставляет
необходимые данные или не поддерживает передачу подтверждения, остановить
реализацию затронутой интеграции и вернуться к пересмотру спеки. Нельзя объявить
клиент поддержанным, заменить происхождение доверием к произвольному пути или
завершить задачу с постоянно неработающими картинками. Во время работы уже
поддержанного адаптера неизвестный формат отключает только операции с картинками
с явной причиной; текстовые операции сохраняются.

## Хук и существующие ограничения

Защитный `PreToolUse` продолжает отклонять очевидные прямые команды Apple Notes
и обращения к NoteStore согласно исходной спеке. В Claude покрываются `Bash`
и `Monitor`. В Codex учитывается нормализованный `Bash` для shell/unified exec,
включая вложенные вызовы Code Mode. Не следует предполагать, что имя hook-события
равно имени функции `exec_command`.

Хук прямого доступа и хук подтверждения вложений имеют разные обязанности:
сбой получения вложений не разрешает произвольный файл. Обычная текстовая
операция не требует билета картинки и не зависит от доступности transcript.

Доверие Codex к хукам проходит через штатный интерфейс клиента. Установщик и
setup-скилл не отключают проверку доверия и не редактируют её хранилище.
Проверяется как установленный и доверенный хук, так и отсутствие действующего
подтверждения вложений до доверия. Хук не обещает блокировать намеренно скрытый
обход, интерактивную передачу команд через уже запущенный shell или чтение базы
другими средствами пользователя.

Не меняются:

- Ровно одна папка; подпапки и «Недавно удалённые» не разрешены.
- Проверка container заметки перед каждой операцией по id в том же скрипте.
- Отказ чтения и изменения защищённых паролем заметок.
- Отказ `notes_append`/`notes_update` для заметок со списками или вложениями.
- Отказ полной замены текста, полученного с пометкой обрезки.
- Передача данных JXA аргументами/временным файлом, без внедрения в скрипт.
- Различение таймаута записи: действие могло примениться, требуется перечитать.
- Отсутствие Full Disk Access и сетевых функций во время работы сервера.
- Удаление и перезапись не добавляются плагином в автоматически разрешённые
  инструменты. Решения о подтверждениях остаются у клиента и пользователя.

## Ошибки и диагностика

Ошибки настройки, подтверждения вложения, формата/размера файла и доступа к
Apple Notes различаются. Для неизвестного формата клиента ответ сообщает, что
происхождение вложения не подтверждено, и предлагает проверить версию/подключение
плагина. Он не предлагает скопировать произвольный файл в разрешённый каталог.

Диагностика не печатает содержимое заметок, пользовательских сообщений,
картинок, ticket-файлов и конфигурации других MCP. В публичные тестовые примеры
не попадают реальные имена папок, пути пользователя, идентификаторы его сессий
и содержимое его диалогов.

## Проверки и критерии приёмки

### Автоматические

1. Общий набор текущих тестов, typecheck, воспроизводимость `dist/`.
2. Манифесты и оба каталога: относительные пути существуют в устанавливаемом
   пакете, манифест Codex выбирает свои hooks/MCP/setup, версии согласованы,
   старые имена установки и записи остальных Claude-плагинов сохранены.
3. Независимые настройки, неверная версия/повреждение файла, пустая и неоднозначная
   папка, неуспешная перенастройка, сохранение после обновления пакета.
4. Обезличенные события обоих клиентов: вложение пользователя допускается;
   текстовый путь, tool-result, другой диалог и неизвестная форма не допускаются.
   Вложение старого сообщения текущего диалога допускается, если доступно.
5. Ticket: привязка к аргументам/инструменту и хосту, однократность, срок,
   неизвестный билет, подмена копии, параллельные диалоги, повтор после таймаута.
6. Все файловые проверки, включая замену источника между проверкой и копированием,
   символическую ссылку, неверную сигнатуру, превышение размера, несколько картинок
   с одной недопустимой. При отказе нет вызова записи Apple Notes.
7. Защитный хук: формы команд обоих клиентов, нормализованный Bash Codex,
   вложенные вызовы Code Mode, безопасные команды; отказ не зависит от того,
   распознаны ли вложения диалога.

### Живая приёмка в обоих клиентах

Использовать отдельные временные тестовые папки и синтетические заметки;
реальные пользовательские заметки не изменять. В отчёте указать версии
клиентов/macOS/Node, способ установки, число проверок, результат каждой
категории и существенные ограничения. Следы удалённых тестовых заметок в
«Недавно удалённых» обозначить перед запуском проверки.

| Сценарий | Ожидаемый результат |
|---|---|
| Установить Apple Notes из `YarikMix/agent-utils` в каждый клиент | Пакет запускается без ручной сборки и отдельной записи MCP |
| Выбрать разные тестовые папки в Claude и Codex | Каждый клиент работает только со своей папкой |
| Перенастроить один клиент и перезапустить его MCP | Второй сохраняет прежнюю настройку |
| Обновить пакет без очистки данных | Выбор папки сохранён |
| Прочитать, найти, создать, дописать, заменить и удалить тестовую заметку | Все семь инструментов работают в выбранной папке |
| Передать id заметки чужой папки/подпапки | Операция отклонена, чужой текст не раскрыт |
| Прикрепить синтетическую картинку в диалог и создать заметку | В Apple Notes видна одна исправная картинка |
| Вставить вложение предыдущего сообщения того же диалога | Успех при доступных данных происхождения |
| Передать путь посторонней картинки, в том числе во временном каталоге клиента | Отказ до изменения заметки |
| Попробовать использовать вложение другого параллельного диалога | Отказ до изменения заметки |
| Передать неподдержанную форму контекста | Понятный отказ картинке; текстовые операции работают |
| Вызвать прямую команду Apple Notes после доверия установленному хуку | Отказ до выполнения команды, в Codex также через Code Mode |
| Изменить заметку со списком, чек-листом или вложением | Отказ; содержание и вложения сохраняются |

Живые проверки дополняют автоматические; успешный мок или запуск сырого сервера
не заменяет установку из каталога и реальное пользовательское вложение.

## Доставка и миграция

Обновить корневой README и действующие инструкции плагинов на новый URL,
описать две команды подключения маркетплейса, настройку Codex и ограничения
картинок версии `2.0.0`. Сохранить идентификатор `yarikmix-plugins`, поэтому
имя `apple-notes-folder@yarikmix-plugins` не меняется.

Подключение каталога в Claude: `/plugin marketplace add YarikMix/agent-utils`.
В Codex: `codex plugin marketplace add YarikMix/agent-utils`.
После подключения плагин выбирается в штатном интерфейсе установки клиента;
добавление каталога само по себе не считается установкой или проверкой плагина.

Не переписывать конфигурацию установленных клиентов целиком, не использовать
ручное добавление MCP вместо проверки плагина и не переключать другие плагины.
Локальные git remote обновляются на новый URL отдельно, сохраняя принятый
транспорт. Основной checkout и другие worktree не переименовываются попутно.
Публикация изменений и установка на пользовательский профиль выполняются
после реализации и проверки, по дальнейшему согласованному плану.
