# TypeScript Native LSP для Codex и переименование репозитория

Дата: 2026-10-13. Статус: на согласовании.

## Цель и согласованный объём

Пользователь хочет устанавливать `typescript-native-lsp` через маркетплейс Codex и пользоваться навигацией нативного сервера TypeScript 7. Репозиторий `YarikMix/claude-plugins` переименовывается в `YarikMix/agent-plugins`. Выбран собственный MCP-адаптер, который соединяет Codex с `tsc --lsp --stdio`.

В этой задаче поддержку Codex получает только `typescript-native-lsp`. Каталог Claude Code продолжает содержать все три существующих плагина. Изменения README других плагинов ограничиваются новым адресом репозитория. Портирование `selectel-ops` и `apple-notes-folder` в Codex отложено пользователем.

Успех: установка из нового GitHub-адреса даёт Codex рабочий MCP-инструмент навигации, который отвечает через `typescript-go` версии 7 или новее, видит сохранённые изменения исходников и завершает принадлежащий ему сервер вместе с MCP-процессом.

## Исходное состояние и основания решений

Исследована актуальная `origin/main`, SHA `eed751aca38991ab547a314a4401ce84fe54e0cf`. В репозитории уже есть `.claude-plugin/marketplace.json`, три плагина, спеки и планы. У TypeScript-плагина сейчас только README и лицензия; `lspServers` объявлен в каталоге Claude Code с `strict: false`.

Основания:

- [Исходная спека TypeScript-плагина](2026-09-19-typescript-native-lsp-design.md) сознательно выбирает глобальный `tsc` из PATH ради независимости от пакетного менеджера. Имя маркетплейса после публикации фиксировано, поскольку входит в идентификаторы установок.
- [Исследование нативного сервера для Serena](2026-09-20-serena-typescript-native-design.md) установило на 7.0.2: `textDocumentSync` может быть объектом; при `includeDeclaration: false` теряются импорты и реэкспорты; готовность нельзя определять ожиданием несуществующего `$/progress`.
- [Официальная документация OpenAI](https://developers.openai.com/plugins/build/plugins) описывает каталог `.agents/plugins/marketplace.json`, пакеты со скиллами и MCP, включая переносимый `plugin.json` и `mcp.json`.
- [Запрос прямой интеграции LSP в Codex](https://github.com/openai/codex/issues/8745) открыт на дату исследования. Для этой работы выбирается документированный MCP-интерфейс; наличие `lspServers` само по себе не считается поддержкой Codex.
- На текущей машине установлена Codex CLI 0.162.1. Её справка подтверждает `codex plugin marketplace add` и `codex plugin add`. `tsc` в PATH текущей машины пока не найден; реальные пробы входят в последующую реализацию, а не считаются выполненными.

Изменяется только прежнее решение «плагин без кода»: Codex требует адаптера. Глобальный компилятор, отсутствие автоматической установки TypeScript и отсутствие диагностики типов сохраняются. Спека Serena служит источником наблюдений, но её код, зависимости и интеграция не переносятся.

## Устройство пакета и установка

У плагина две точки входа для разных хостов. Codex-пакет лежит в подкаталоге `codex/`, чтобы Claude Code не обнаруживал его MCP-конфигурацию и скилл вместе со своим LSP-плагином.

```text
.claude-plugin/marketplace.json             # каталог Claude Code, все три плагина
.agents/plugins/marketplace.json           # каталог Codex, один TypeScript-плагин
plugins/typescript-native-lsp/
  README.md
  LICENSE
  codex/
    plugin.json                            # переносимый манифест, версия 1.1.0
    mcp.json                               # один локальный stdio MCP-сервер
    package.json
    package-lock.json
    skills/typescript-native-lsp/SKILL.md
    src/                                   # адаптер, клиент LSP и состояние документов
    test/
    scripts/                               # сборка и проверка готового артефакта
    dist/server.js                         # готовый бандл, хранится в Git
```

Оба каталога имеют `name: yarikmix-plugins`. Имя плагина остаётся `typescript-native-lsp`. Запись Codex с локальным источником указывает на `./plugins/typescript-native-lsp/codex`; путь разрешается от корня репозитория. У записи есть требуемые поля политики установки и аутентификации; установка доступна по выбору пользователя. Каталог Codex не содержит записей остальных плагинов.

В `plugin.json` используется переносимая схема Agent Plugins, имя, версия, описание, автор и лицензия MIT. `mcp.json` использует соответствующую схему MCP и явно объявляет транспорт `stdio`. Команда MCP: `command: node`, `args: ["./dist/server.js"]`, `cwd: "./"`. Codex разрешает этот cwd от установленного корня пакета; клиент LSP запускает TypeScript уже с cwd рабочей области. Работоспособность проверяется установкой из каталога и запуском кэшированной копии, не только ручным стартом бандла. Жёстких путей пользователя, обращения к основному чекауту и зависимости от его `node_modules` нет. Разрешение относительного cwd видно в [реализации загрузчика MCP Codex](https://github.com/openai/codex/blob/main/codex-rs/codex-mcp/src/agent_plugin_config.rs); тест установки проверяет именно установленную версию CLI.

Для пользователя требуются Node.js 20+ и TypeScript 7+, доступный как `tsc` в PATH. На установке и старте MCP ничего не скачивается и не собирается. TypeScript не встраивается в бандл. Зависимости разработки фиксируются lock-файлом с публичным npm registry, без внутренних адресов и учётных данных. Готовый бандл воспроизводимо собирается из исходников по существующему примеру `apple-notes-folder`.

Команды установки:

```text
codex plugin marketplace add YarikMix/agent-plugins
codex plugin add typescript-native-lsp@yarikmix-plugins
```

README отдельно описывает команды Claude Code, команды Codex, требования, перезапуск сессии, проверку связи и ограничения. Версия записи TypeScript в каталоге Claude Code повышается до 1.1.0 как версия расширенного пакета; команда запуска LSP и карта расширений сохраняются. У остальных плагинов версии не меняются.

## Компоненты и владение состоянием

1. **MCP-сервер** использует официальный MCP SDK, публикует один инструмент `typescript_lsp`, проверяет входные данные и преобразует ответы в согласованный формат. stdout отведён протоколу MCP; сообщения и логи идут только в stderr.
2. **Запуск TypeScript** разрешает `tsc` из PATH, проверяет мажорную версию и запускает нативный сервер с `--lsp --stdio`. Поиск локальной зависимости проекта и fallback на TypeScript 6 отсутствуют. На Windows стандартный npm shim разрешается до запускаемого файла пакета: пользовательские строки не подставляются в shell-команду. Поддерживаются пути с пробелами. Процесс, которому принадлежат потоки LSP, должен быть непосредственно управляемым дочерним процессом; дополнительный launcher не должен оставлять нативный процесс после завершения адаптера.
3. **Клиент LSP** управляет `initialize` → `initialized`, запросами JSON-RPC, отменой, таймаутами, capabilities и завершением. Для транспорта и типов используются `vscode-jsonrpc` и `vscode-languageserver-protocol`, без собственного разбора кадров. Учитываются обе формы `textDocumentSync`. `workspace/configuration` получает корректный ответ, уведомления прогресса и логов не блокируют запросы. Клиент объявляет только реально реализованные capabilities. Запрос `workspace/applyEdit` отклоняется: инструмент не меняет файлы.
4. **Состояние документов** читает сохранённые файлы, отправляет `didOpen` и `didChange`, ведёт версии и обновляет состояние перед запросами. Очередь предотвращает нарушение порядка изменений и запросов.

В MCP-процессе одна рабочая область и один сервер TypeScript. `workspace_root` передаётся явно как абсолютный существующий каталог. Первый запрос связывает процесс с этим корнем; последующий запрос с другим корнем возвращает `WORKSPACE_MISMATCH` с указанием, что нужна новая сессия/MCP-процесс. Никаких предположений о том, что cwd MCP совпадает с каталогом проекта, нет. Монорепозиторий используется как одна рабочая область с общим корнем; отдельный оркестратор нескольких рабочих областей в эту задачу не входит.

MCP-сервер поднимается без запуска TypeScript. `tools/list` работает даже при отсутствующем `tsc`; установка плагина не создаёт компилятор в сессиях без TypeScript. Проверка версии и запуск выполняются при первом запросе навигации.

## Контракт MCP-инструмента

`typescript_lsp` объявляет `readOnlyHint: true`, `destructiveHint: false`. Поддерживаются только операции ниже, без произвольного проксирования LSP-методов.

| operation | Метод LSP | Обязательные данные помимо workspace_root |
|---|---|---|
| `goToDefinition` | `textDocument/definition` | file_path, line, column |
| `findReferences` | `textDocument/references` | file_path, line, column |
| `hover` | `textDocument/hover` | file_path, line, column |
| `documentSymbol` | `textDocument/documentSymbol` | file_path |
| `workspaceSymbol` | `workspace/symbol` | query |
| `goToImplementation` | `textDocument/implementation` | file_path, line, column |
| `prepareCallHierarchy` | `textDocument/prepareCallHierarchy` | file_path, line, column |
| `incomingCalls` | `callHierarchy/incomingCalls` | item_id |
| `outgoingCalls` | `callHierarchy/outgoingCalls` | item_id |

`file_path` — абсолютный путь существующего файла внутри рабочей области после нормализации и разрешения симлинков. Расширения совпадают с текущим плагином: `.ts`, `.tsx`, `.js`, `.jsx`, `.mts`, `.cts`, `.mjs`, `.cjs`. Запросы к другим расширениям отклоняются. Строки и столбцы начинаются с 1; столбцы считаются в кодовых единицах UTF-16, как LSP. Позиции проверяются относительно содержимого файла и преобразуются в нумерацию LSP с 0. Столбец на конце строки допустим, отрицательные и выходящие за строку позиции — ошибка.

`findReferences` всегда запрашивает `includeDeclaration: true`: результат включает определение, импорты и реэкспорты. Параметра для исключения определения в первой версии нет. Это избегает уже измеренной потери импортов без неявного изменения результатов клиента.

Для списков используются `offset` (по умолчанию 0) и `limit` (по умолчанию 100, максимум 500). Ответ сообщает `total`, `has_more` и содержит выбранную страницу. Для одиночного hover эти параметры неприменимы. Значимые иерархии и диапазоны сохраняются; элементы верхнего уровня разбиваются на страницы, вложенные элементы не выдаются как самостоятельные плоские символы. Ответы `Location`/`LocationLink` и `SymbolInformation`/`DocumentSymbol` нормализуются с сохранением пути, диапазона, имени и вида символа. Источники в `node_modules` или вне корня, возвращённые самим LSP, могут быть показаны как местоположения; это не разрешает инструменту открывать такие файлы отдельным запросом.

`prepareCallHierarchy` возвращает краткую информацию и непрозрачный `item_id` для каждого результата. Исходный `CallHierarchyItem`, включая `data`, хранит адаптер; принимается только выданный текущим процессом идентификатор. Изменение документов и перезапуск TypeScript инвалидируют эти идентификаторы. Скилл при `STALE_ITEM` повторяет подготовку. Для дальнейшего перехода элементы ответов входящих и исходящих вызовов также получают идентификаторы с теми же правилами.

Ответ содержит `operation`, применённый корень и `server_info` (имя и версию из `initialize`), а также данные операции. `null` и пустые списки LSP превращаются в успешный пустой результат, а не ошибку. Ошибки инструмента используют MCP `isError: true` и включают стабильный код, краткое описание и способ исправления. Результат крупнее 1 МиБ после выбора страницы не обрезается молча: возвращается `RESULT_TOO_LARGE` с предложением сузить query или уменьшить limit.

## Актуальность данных и жизненный цикл

Перед каждым запросом перечитываются все уже открытые адаптером документы; изменившимся файлам увеличивается версия и отправляется полная замена содержимого через `didChange`. Для incremental sync используется корректное событие полной замены, допустимое протоколом; не требуется вычислять diff текста. Удалённый документ закрывается через `didClose`, его старый текст больше не используется. Новый запрашиваемый файл открывается перед операцией. Не сохраняются результаты прошлых операций навигации.

Чтобы изменения импортируемых, но ещё не открытых файлов и конфигурации не оставались в кэше TypeScript, клиент обслуживает регистрацию и снятие `workspace/didChangeWatchedFiles` в пределах рабочей области и отправляет события изменений с диска по запрошенным сервером шаблонам. Если сервер не регистрирует наблюдение, адаптер наблюдает поддержанные исходники и JSON-конфигурацию рабочей области, исключая рекурсивный обход `.git` и `node_modules`. Изменение установленного содержимого node_modules в ходе сессии требует нового MCP-процесса. События коалесцируются, обработчик не создаёт по процессу на файл. До обработки запроса накопленные события отправляются серверу. Изменение `tsconfig.json`, создание и удаление исходника покрываются проверками. Несохранённые буферы редактора недоступны: источником истины остаётся диск.

Первый запрос ждёт завершения LSP-handshake и открытия требуемого документа; без постоянной задержки и без ожидания необъявленной готовности по `$/progress`. Полнота ответа на холодном сервере проверяется отдельным тестом импортов и реэкспортов.

Таймаут проверки версии — 5 секунд, инициализации — 30 секунд, операции LSP — 30 секунд. На отмену/таймаут запроса отправляется `$/cancelRequest`. Падение дочернего процесса отклоняет ожидающие запросы и очищает состояние LSP и идентификаторы; привязка MCP-процесса к рабочей области сохраняется. Текущий запрос не повторяется молча; следующий может создать новый сервер и заново открыть документы.

Закрытие stdin MCP, `SIGINT` и `SIGTERM` инициируют `shutdown` и `exit` LSP. На корректное завершение даётся 2 секунды, затем принудительно завершается принадлежащий адаптеру дочерний процесс. Сторонние процессы TypeScript не затрагиваются. Повторное закрытие безопасно.

Коды ошибок: `INVALID_ARGUMENT`, `INVALID_WORKSPACE`, `WORKSPACE_MISMATCH`, `FILE_NOT_FOUND`, `UNSUPPORTED_FILE`, `TSC_NOT_FOUND`, `UNSUPPORTED_TYPESCRIPT_VERSION`, `LSP_INITIALIZATION_FAILED`, `UNSUPPORTED_OPERATION`, `LSP_TIMEOUT`, `LSP_EXITED`, `STALE_ITEM`, `RESULT_TOO_LARGE`. Проверка версии до запуска сообщает фактическую найденную версию; сервер проверяется по собственному `serverInfo`. Ошибка возможностей сервера отличается от успешного пустого результата.

## Скилл использования

Скилл входит только в пакет Codex. Он описывает выбор operation, определение корня проекта из контекста текущей сессии, абсолютные пути, нумерацию позиций, работу с `item_id`, пагинацию и действия при ошибках. Агент предпочитает MCP для семантической навигации; текстовый поиск остаётся доступен для строк, конфигурации, документации и поиска исходной позиции символа.

После сохранённой правки агент может повторно запросить hover, символы или ссылки: адаптер обязан синхронизировать изменения сам. Скилл не обещает автоматические сообщения об ошибках типов и не заменяет тесты проекта. Диагностика типов проверяется обычной командой проекта или `tsc --noEmit`.

## Переименование и выпуск

Имя GitHub-репозитория меняется на `agent-plugins`; имена маркетплейса и плагинов сохраняются. В актуальных README заменяются ссылки и команды добавления каталога. Исторические спеки и планы остаются документами о прежних решениях; их старые адреса не переписываются массово.

Порядок выпуска: подготовить изменения в отдельной ветке и проверить пакет → переименовать репозиторий на GitHub → обновить remote задачного клона на новый адрес → опубликовать ветку и согласованный способ интеграции → проверить установку из нового GitHub-адреса. Переименование уже запрошено пользователем, но до согласования спеки и плана внешнее состояние не меняется.

Старый адрес проверяется после переименования: документация не объявляет успешную миграцию только по ожидаемому перенаправлению GitHub. Пользователям с установленным Claude-маркетплейсом даются инструкции обновления источника, если его refresh по старому адресу не работает. Не требуется менять `enabledPlugins` или переустанавливать идентификаторы из-за нового имени репозитория. Локальные настройки пользователя в рамках подготовки пакета не меняются.

## Проверки и критерии приёмки

| Проверка | Критерий |
|---|---|
| Два каталога | JSON корректен; Codex видит ровно один плагин; каталог Claude Code сохраняет все три и прежние LSP command/args/extensionToLanguage |
| Готовый артефакт | пересборка побайтно совпадает с dist; запуск кэшированного пакета без node_modules работает; stdout содержит только MCP |
| Версия и запуск | нет tsc и TS 6 дают разные понятные ошибки; TS 7 запускается; путь с пробелами работает; сервер появляется только после первого запроса |
| Контракт и протокол | валидация путей/UTF-16/позиций, обе формы sync capabilities, нормализация вариантов ответов, null, пагинация и неподдержанная capability проверены |
| Навигация с настоящим TS 7 | в тестовом проекте независимо известны все места определения, импорта, реэкспорта и вызовов; проверены девять operations, включая холодный findReferences; имя и версия serverInfo подтверждают нативный сервер |
| После изменений | изменение типа меняет hover; правка открытого и импортируемого файла, создание/удаление исходника и правка tsconfig отражаются в новых ответах без перезапуска MCP |
| Иерархия вызовов | сохранена data сервера; поддельный и устаревший item_id отклоняются; после повторной подготовки запрос проходит |
| Отказы и завершение | таймаут, отмена, падение и повторный запуск не смешивают ответы; EOF/сигнал завершают собственный сервер и не оставляют нативный дочерний процесс |
| Скилл | в новой сессии Codex задача на ссылки/тип приводит к MCP-запросу с корректным корнем и позицией; результат сверяется с независимым эталоном |
| Установка и миграция | локальная установка и установка из YarikMix/agent-plugins работают; новый адрес и поведение старого проверены; повторная установка не меняет идентификаторы |

Протокольные отказы и синхронизацию проверяют управляемые тестовые серверы; фактическую навигацию — настоящий TypeScript 7. Тесты фиксируют наблюдаемое поведение, а не повторяют преобразования реализации. Проба навигации запускается на временном проекте, без изменений реальных рабочих исходников пользователя.

Реальные проверки обязательны на macOS и Windows, поскольку исходный плагин уже использовался на обеих платформах. На macOS проверки выполняет агент в доступном окружении; Windows прогоняется через CI. Linux покрывается тем же CI. Ни одна непроведённая платформенная проверка не маркируется успешной. Точный список команд и устройство фикстуры фиксируются в плане реализации.

## Границы и риски

В объём не входят диагностика через MCP, автопубликация publishDiagnostics, переименование символов, форматирование, code actions, TypeScript 6, локальный подбор компилятора проекта, интеграция Serena, портирование остальных плагинов и публикация в центральный каталог OpenAI.

Расхождение глобального компилятора и версии проекта — прежнее принятое ограничение, которое сохраняется в README. Настройки MCP и разрешение пути к бандлу проверяются на реально установленной Codex CLI; проверка одной схемы не заменяет запуск. Нативный TypeScript может менять capabilities и поведение; тесты записывают фактически проверенную версию. Наблюдатели файлов и завершение дочернего процесса требуют платформенных проверок. Один корень на MCP-процесс явно ограничивает переключение проектов внутри сессии.
