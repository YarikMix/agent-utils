# Импорт ts-mcp и поддержка TypeScript Native LSP в Codex

Дата: 2026-10-14. Статус: согласовано пользователем.

## Цель и выбранный подход

Добавить поддержку Codex только для `typescript-native-lsp` в репозитории пользователя и переименовать GitHub-репозиторий `YarikMix/claude-plugins` в `YarikMix/agent-plugins`. Пользователь выбрал копирование `packages/ts-mcp` из `zachsents/zachs-tools` с дальнейшей доработкой в своём репозитории. Форк монорепозитория не создаётся; исходники адаптера не пишутся заново.

Codex должен устанавливать плагин из маркетплейса и получать навигацию через нативный сервер TypeScript 7. Пакет также сохраняет свои существующие возможности диагностики, переименования и подсказок типов. Текущий плагин Claude Code продолжает запускать LSP напрямую. `selectel-ops` и `apple-notes-folder` остаются только в каталоге Claude Code; их README меняются только в части нового адреса репозитория.

Этот документ заменяет [первоначальную спеку собственного адаптера](2026-10-13-codex-typescript-native-lsp-design.md). Следующий артефакт после его одобрения — отдельный русский план реализации.

## Проверенная база

База целевого репозитория: `origin/main`, SHA `eed751aca38991ab547a314a4401ce84fe54e0cf`.

Импортируемый источник: [zachsents/zachs-tools, packages/ts-mcp](https://github.com/zachsents/zachs-tools/tree/039e5f38503eb5ace3a82a4a55fb6d5e7dce3ce1/packages/ts-mcp), SHA `039e5f38503eb5ace3a82a4a55fb6d5e7dce3ce1`, исходная версия 0.3.7. Не используется плавающий `main` при копировании.

У пакета четыре файла реализации: `src/index.ts`, `src/lsp-client.ts`, `src/pool.ts`, `src/resolve-binary.ts`; есть README, smoke-тест и фикстура, отдельные tsconfig для проверки и сборки. Рабочие зависимости — MCP SDK, Zod и TypeScript 7. У зависимостей разработки есть `workspace:*` на линтер автора; эти настройки монорепозитория переносить не нужно.

Опубликованный npm-пакет 0.3.7 проверен на macOS 26.5.2 arm64, Node 24.21.0, TypeScript 7.0.2, Codex CLI 0.162.1. Codex App Server обнаружил все шесть инструментов, выполнил hover и references. Подтверждены холодные ссылки через импорт/реэкспорт, определения, outline, pull-диагностика и rename в обычном пути.

Найдены дефекты:

1. Путь с пробелами возвращается как `%20`; rename пытается открыть этот несуществующий путь. Символ `#` повреждает URI.
2. Удалённый открытый документ остаётся в состоянии LSP: диагностика импортирующего файла пуста, хотя независимый `tsc` выдаёт TS2307.
3. Закрытие stdin не завершило MCP-процесс в течение 1.5 с; последующий SIGTERM завершил процессы.
4. После правки неоткрытой зависимости немедленный hover может вернуть старый тип. Вне песочницы через 1.5 с получен новый; это задержка актуализации, а не доказательство постоянного зависания.

Проба `inlay_hints` вернула пустой результат без ошибки. Непустые подсказки пока не подтверждены. Windows и Linux не проверены. Установка через маркетплейс ещё не проверена. Все тестовые MCP/LSP-процессы остановлены.

## Что сохраняется и что меняется

| Решение | Итог | Основание |
|---|---|---|
| Источник реализации | копируем пакет автора и правим локально | последнее решение пользователя |
| Имена маркетплейса и плагина | `yarikmix-plugins`, `typescript-native-lsp` | [исходная спека](2026-09-19-typescript-native-lsp-design.md): имена входят в установленные идентификаторы |
| TypeScript для Claude Code | `tsc` из PATH, версия 7+ | прежний работающий контракт |
| TypeScript для готового Codex-пакета | глобальный TS 7 из PATH, либо явный `TSC_PATH` на нативный бинарник | установка плагина не должна требовать npm install или скачивания компилятора при старте; бандл JavaScript не содержит платформенный бинарник |
| Шесть MCP-инструментов автора | сохраняются имена, аргументы и нумерация позиций с 0 | переиспользуем проверенный API, не переписываем под прежний единый инструмент |
| Недостающая навигация | добавляются definition, workspace symbols, implementations и call hierarchy | сохраняем объём навигации первоначально выбранного дизайна |
| Проекты | сохраняется пул серверов по корням tsconfig | существующее поведение пакета; ограничение одного корня из предыдущей спеки отменяется |
| Диагностика и rename | сохраняются | входят в выбранный пользователем пакет; прежнее ограничение собственного адаптера отменяется |

Нативный бинарник берётся из глобальной установки TypeScript, не из автоматически подобранной зависимости проекта. Расхождение его версии с проектом документируется, как у исходного плагина. TypeScript 6 и fallback на tsserver не добавляются.

Пакет остаётся внутри `codex/`, чтобы Claude Code не обнаруживал его MCP-конфигурацию и скилл вместе со своим прямым LSP. В каталог Codex входит только этот пакет; относительный `source.path` — `./plugins/typescript-native-lsp/codex` от корня репозитория.

MIT явно указана в исходных README и package.json. Отдельного LICENSE в исходном пакете и корне монорепозитория при проверке нет. В импорт добавляется полный стандартный текст MIT с `Copyright (c) Zach Sents`, без выдуманного года. Авторство заимствованной реализации сохраняется в исходниках/notice, метаданные самого плагина могут отдельно называть владельца Yaroslav Mihalev. Лицензия существующего Claude-плагина не подменяет уведомление автора импортируемого кода.

`UPSTREAM.md` фиксирует URL, SHA, исходный путь, версию, список перенесённых файлов и местные изменения. Обновление upstream выполняется осознанным сравнением с этим SHA; автоматического скрипта синхронизации и подмодулей нет. Файлы редактора и линтеров автора, глобальные AGENTS.md и настройки остальных пакетов монорепозитория не копируются.

Внутренний package.json имеет собственное имя, `private: true`; npm-публикация под `@zachsents/ts-mcp` не выполняется. Runtime использует Node.js 20+. Рабочие библиотеки включаются в один ESM-бандл `dist/server.js`; TypeScript становится зависимостью разработки для сборки и проверок, его нативный бинарник в бандл не включается. Версии фиксируются собственным lock-файлом с публичным npm registry. Из установок плагина ничего не загружается при запуске.

Сборка и её проверка следуют примеру `apple-notes-folder`: dist хранится в Git, повторная сборка во временный каталог побайтно сверяется с сохранённым артефактом. Нужные лицензионные notices библиотек сохраняются. Тесты самостоятельны и не требуют workspace-пакетов линтинга монорепозитория; исходный smoke переносится и дополняется проверками с утверждениями результатов.

## Установка и конфигурация Codex

Манифест Codex использует переносимый `plugin.json` и `mcp.json` по [документации OpenAI](https://developers.openai.com/plugins/build/plugins). Имя плагина — `typescript-native-lsp`, версия расширенного пакета — 1.1.0. Структура скилла — обычный `skills/typescript-native-lsp/SKILL.md`, без симлинка.

В mcp.json объявлен один сервер `typescript_native_lsp` с `type: stdio`, `command: node`, `args: ["./dist/server.js"]`, `cwd: "./"`. Codex разрешает cwd от установленного корня пакета; проект определяется по абсолютному пути запрашиваемого файла. Использование корня пакета как cwd не меняет выбранный tsconfig проекта.

Каталог `.agents/plugins/marketplace.json` имеет `name: yarikmix-plugins`, только одну запись, относительный локальный источник, требуемые поля политики установки/аутентификации и категорию. Установка доступна по выбору пользователя. Аутентификация внешнего сервиса плагину не нужна.

```text
codex plugin marketplace add YarikMix/agent-plugins
codex plugin add typescript-native-lsp@yarikmix-plugins
```

Пробы выполняются сначала из локального каталога, затем из нового GitHub-адреса. Проверяется именно установленная кэшированная копия без node_modules исходного чекаута, обнаружение скилла, tools/list и реальные вызовы. Постоянные MCP-настройки пользователя при пробах не редактируются.

## Запуск компилятора и пул проектов

`TSC_PATH`, если задан, указывает на нативный бинарник TypeScript. Иначе адаптер находит `tsc` в PATH и разрешает стандартную глобальную установку до нативного бинарника пакета TypeScript. Обрабатываются POSIX-симлинки и Windows npm shim; строки пользователя не подставляются в shell-команду. Нативный процесс управляется напрямую, чтобы launcher Node не оставлял дочерний процесс. Проверка `--version` ограничена 5 с и отклоняет мажорную версию ниже 7.

MCP-handshake и tools/list работают без запуска TypeScript; его разрешение и проверка выполняются при первом запросе к файлу. Инициализация LSP — до 30 с; запрос — до 30 с. stdout используется только для MCP; stderr дочернего процесса потребляется и направляется в лог с ограничением шумных сообщений.

Корень проекта определяется от абсолютного file вверх до ближайшего tsconfig.json; при его отсутствии — каталог файла, как в upstream. Каждый корень получает отдельный LSP-клиент; клиент запускает TypeScript с cwd этого корня и корректным rootUri. Одновременные первые запросы к одному корню разделяют одну инициализацию, а не запускают дубли. Сохраняется idle timeout 5 минут. Падение процесса отклоняет ожидающие запросы; следующий запрос может создать новую сессию, старые идентификаторы call hierarchy недействительны.

## Инструменты и контракт

Сохраняются шесть инструментов upstream:

| Инструмент | Результат | Семантика |
|---|---|---|
| `hover` | тип/документация и первое определение | чтение |
| `diagnostics` | свежая диагностика файла и доступные правки quick fix как данные | чтение, без применения правок |
| `references` | ссылки, включая объявление, импорты и реэкспорты | чтение, includeDeclaration=true |
| `outline` | символы файла и вложенные элементы | чтение |
| `rename` | применение переименования к файлам | запись |
| `inlay_hints` | подсказки типов и параметров диапазона | чтение |

Позиции остаются с 0, столбец character — UTF-16. Отрицательные, дробные и выходящие за содержимое позиции отвергаются. Пустой ответ отличается от ошибки протокола; инструмент не выдаёт «No errors» при ошибке разбора ответа LSP. Явно запрошенный отсутствующий файл даёт ошибку, а не пустые данные. При удалении зависимого документа обновляется сессия, описанная ниже.

Добавляются шесть инструментов с той же нумерацией:

| Инструмент | Метод LSP | Вход |
|---|---|---|
| `definition` | textDocument/definition | file, line, character |
| `workspace_symbols` | workspace/symbol | file для выбора проекта, query |
| `implementations` | textDocument/implementation | file, line, character |
| `prepare_call_hierarchy` | textDocument/prepareCallHierarchy | file, line, character |
| `incoming_calls` | callHierarchy/incomingCalls | file для выбора проекта, item_id |
| `outgoing_calls` | callHierarchy/outgoingCalls | file для выбора проекта, item_id |

Итого публикуются 12 инструментов. Скилл и README называют именно этот API; единого инструмента `typescript_lsp` из прежней спеки нет. `definition` возвращает все определения, а не только первое, как hover. Поддерживаются оба стандартных варианта Location/LocationLink и SymbolInformation/DocumentSymbol. Необъявленная capability приводит к понятной ошибке; не появляется ложный успешный пустой результат.

Элементы call hierarchy получают непрозрачный item_id; полный LSP CallHierarchyItem с data хранится клиентом. Путь file должен выбрать тот же проект, который выдал идентификатор. Поддельные, принадлежащие другому проекту и устаревшие идентификаторы отклоняются. Изменение синхронизируемых документов или перезапуск клиента инвалидирует идентификаторы. Входящие/исходящие вызовы сохраняют диапазоны и получают идентификаторы для дальнейшего обхода.

Read-only инструменты имеют соответствующие MCP annotations; rename объявляется инструментом записи. Скилл выполняет rename по явной просьбе пользователя, а не для навигации. Переименование сначала получает и валидирует полный WorkspaceEdit. Отказывают неоднозначные/неподдержанные правки и ресурсные операции. Проверяются позиции и доступность файлов до первой записи; частичный результат при ошибке не выдаётся за успех. Сохраняются EOL и BOM. Границы доступа остаются границами проекта, с которым явно работают: произвольного вызова методов LSP и shell-команд через вход инструмента нет.

## Исправление URI, документов и завершения

1. **URI.** Для корней и файлов применяются штатные Node pathToFileURL/fileURLToPath. Возвращённое местоположение обязано быть реальным путём, а не URI с процентным кодированием. Проверяются пробелы, кириллица, #, %, Windows drive paths. Это распространяется и на пути WorkspaceEdit при rename.
2. **Удалённые документы.** refreshOpenDocuments на ENOENT отправляет didClose, удаляет документ из карты и информирует LSP об удалении файла. Другие ошибки чтения не игнорируются как удаление. Последующий diagnostics импортирующего файла обязан показать TS2307, совпадающий с независимым компилятором.
3. **Актуальность.** Существующие открытые документы перечитываются до операции, версии увеличиваются, обновления сериализуются. Уведомления изменения файлов обслуживаются и отправляются перед запросом. Для неоткрытых зависимостей допускается асинхронная обработка файлового события нативным сервером; проверка нового типа выполняется в пределах 2 с без постоянной задержки каждого запроса. README и скилл предупреждают об этом коротком интервале и предлагают повторить запрос после правки; мгновенная актуальность не обещается. Изменение tsconfig и создание исходника проверяются тем же способом.
4. **EOF и сигналы.** end/close stdin, SIGINT и SIGTERM приводят к единому идемпотентному завершению всех клиентов пула, idle timers и ожидающих запросов. Клиент посылает shutdown/exit; максимум через 2 с завершается его собственный процесс. Другие процессы TypeScript не затрагиваются. Ошибка инициализации не должна оставлять процесс вне пула.

Клиент принимает обе формы textDocumentSync и не ждёт несуществующих событий готовности tsserver. Холодный поиск ссылок через реэкспорт должен сразу включать все ожидаемые места. При cancel/таймауте отправляется $/cancelRequest; ответ на отменённый запрос не приписывается следующему. Последовательность LSP-запросов и изменений одинакова при параллельных MCP-вызовах.

## Скилл, документация и выпуск

Скилл учит выбирать из 12 MCP-инструментов, использовать абсолютные пути и позиции с 0, работать с hierarchy item_id, повторять запрос после изменения зависимости при задержке и интерпретировать ошибки. Для диагностики применяет diagnostics, а для полной проверки проекта — его typecheck/tests. Автоматические push-сообщения об ошибках типов не обещаются.

Корневой README показывает две инструкции установки и матрицу поддержки плагинов. README TypeScript-плагина разделяет прямой LSP Claude Code и MCP Codex, описывает глобальный TS 7, TSC_PATH, возможность диагностики Codex и записывающий rename. В обеих инструкциях источником становится `YarikMix/agent-plugins`. Исторические спеки/планы массово не переписываются.

Имя маркетплейса и идентификаторы установок сохраняются. Версия TypeScript-пакета в обоих каталогах — 1.1.0; у остальных плагинов версии не меняются. Команда, аргументы и extensionToLanguage Claude Code остаются прежними. Переименование GitHub-репозитория выполняется после проверки подготовленного пакета; затем обновляется origin задачного клона и проверяется установка из нового адреса и поведение прежнего URL. Запрос пользователя уже разрешает само переименование; повторное общее разрешение для него не требуется.

Публикуются готовые артефакты и исходники в репозитории пользователя, не npm-пакет автора и не центральный каталог OpenAI. Заявка или PR в upstream не открывается в этой задаче.

| Изменения | правка открытого файла и зависимости, создание/удаление файла и изменение tsconfig отражаются в ответах; неоткрытая зависимость обновляется не позднее 2 с в проверенной среде |
| Параллельность/отказы | два холодных запроса создают один сервер на проект; разные проекты изолированы; таймаут/отмена/падение не оставляют процессы и не смешивают ответы |
| Запись rename | изменения совпадают с ожидаемым diff, EOL/BOM сохранены; после rename проходит независимый typecheck; неполный или ошибочный WorkspaceEdit не применяется частично |
| Совместимость Claude Code | три записи каталога сохранены, TypeScript LSP запускается по прежнему контракту; MCP Codex не активируется как второй сервер Claude Code |
| Платформы | реальные проверки macOS и CI Windows/Linux; не выполненные проверки называются явно и не считаются успешными |

Каждый найденный дефект сначала воспроизводится регрессионной проверкой на импортированной базе, затем исправляется. Используются протокольные тесты с управляемыми серверами и реальные пробы TypeScript 7 на временных проектах. Проверка через Codex App Server подтверждает обнаружение и вызовы; новая сессия агента проверяет загрузку и применение скилла.

## Границы

Не добавляются универсальный выбор языков, TypeScript 6, подбор компилятора node_modules проекта, автоматическая установка зависимостей при запуске, форматирование, применение code actions, отдельная интеграция Serena и поддержка Codex для других плагинов. Стратегия обновления импорта — ручная, по зафиксированному SHA. Результаты MCP не заменяют сборку и тесты проекта.

## Дальнейший порядок

Пользователь проверяет эту письменную спеку. После одобрения используется superpowers:writing-plans, план отдельно показывается для ревью и выбора способа исполнения. Импорт исходников, исправления, манифесты и переименование GitHub выполняются после этого этапа.
