# Peekaboo Control: управление macOS через Desktop Bridge

Дата: 2026-10-19. Статус: описание для проверки перед реализацией.

## Назначение

Дать новому агенту полный доступный инструментарий Peekaboo без повторного
исследования установки и интерфейсов. Пользователь выбрал основной путь
Peekaboo MCP → Desktop Bridge; CLI дополняет его отсутствующими операциями
и диагностикой. Навык должен работать на готовом Mac и помогать настроить
другой Mac после разрешения пользователя на недостающие компоненты.

Результат — документационный плагин `peekaboo-control` версии `1.0.0`
для Codex и Claude Code в публичном `YarikMix/agent-utils`, затем установка
его скилла в текущий Codex. Собственный CLI, MCP-сервер и фоновый сервис
не разрабатываются. Установка документационного плагина не подключает MCP.

## Согласованное поведение

1. Для macOS GUI агент обнаруживает зарегистрированные инструменты и их
   актуальные схемы, локальные версии CLI/Desktop и состояние Bridge.
   Для браузера и приложений с подходящим специализированным инструментом
   использует его; для физического iPhone — `iphone-control`, если доступен.
   Указания по iPhone должны содержать публичную ссылку на навык на случай
   поштучной установки. Навык не заменяет управление симулятором.
2. На готовом Mac агент проверяет соединение и права через фактический MCP,
   затем действует. Не начинает с установки, реконфигурации или обновления.
3. MCP явно подключён к сокету работающего Desktop Bridge через
   `peekaboo mcp serve --bridge-socket <локальный-сокет>`. Desktop — host,
   а не второй MCP-сервер. Автовыбор host недостаточен как доказательство
   использования Desktop. Путь к сокету и бинарнику определяется на Mac.
4. Основной путь действий — MCP. CLI допустим для операции, которой нет
   в MCP, другого документированного режима и диагностики. Перед командой
   читать актуальный leaf `--help`, проверять цель и ограничения.
   Отказ политики MCP не разрешает обход через CLI.
5. macOS Screen Recording, Accessibility и Event Synthesizing отличаются
   от политики MCP. Текущий MCP по умолчанию background-only даже при всех
   системных разрешениях. Foreground и temporary clipboard — отдельные
   grants; без явного разрешения пользователя их не включать. Если нужное
   действие требует grant, объяснить конкретный блокер и запросить его,
   не предлагать скрытый обход. Учесть ранее данную авторизацию в сессии.
6. Рабочий цикл: свежее наблюдение → одно действие → проверка смыслового
   результата. Opaque element IDs передавать без изменения; после смены
   состояния не использовать устаревшие снимки и цели. Учитывать размеры
   изображения, масштаб и систему координат. Для точных ожиданий
   предпочитать доступный `verify_state` произвольной паузе.
7. После таймаута или неизвестного исхода сначала наблюдать состояние.
   Не повторять потенциально уже выполненное действие вслепую. При смене
   процесса перепроверять identity; большие decimal identity хранить
   строкой, если это предусмотрено схемой.
8. Clipboard использовать только в рамках разрешённого режима и задачи.
   После временного использования выполнить предусмотренное восстановление;
   не затирать более новое содержимое пользователя. Не читать clipboard
   для обычной диагностики соединения.

## Первый запуск на другом Mac

Сначала read-only инвентаризация: macOS, Desktop, CLI, доступные MCP tools,
живой Bridge и системные права. Отсутствие инструмента в текущей сессии
отличать от отсутствия установки: возможна необходимость перезапуска клиента.

Если компонентов не хватает, перечислить именно недостающие Desktop, CLI,
подключение MCP/Bridge и запросить разрешение на их установку/настройку.
Это явное требование пользователя к переносимому навыку. После согласия
установить недостающее по актуальным официальным инструкциям и проверить.
Если установка уже разрешена в этой сессии, повторно не спрашивать.

Предусмотреть Codex и Claude Code: сначала установить фактический клиент
и область конфига, затем предложить минимальную запись MCP с абсолютными
локальными путями. Сохранять комментарии и соседние записи; не печатать
секреты и полный конфиг. Backup держать приватно. Перезапускать только свой
проверочный процесс, для пользовательского клиента попросить перезапуск,
если нужен. Не завершать чужие процессы и сессии.

Bridge предоставляет Desktop; не добавлять второй listener или daemon
вместо исправления явного подключения. Не ослаблять проверку TLS, подпись
приложения или macOS security для успешной установки. Системные диалоги
и переключатели разрешений подтверждает пользователь. Не диагностировать
ошибку sandbox/daemon lock как отсутствие TCC без отдельного свидетельства.

## Состав и ответственность файлов

```text
plugins/peekaboo-control/
  .claude-plugin/plugin.json
  .codex-plugin/plugin.json
  README.md
  LICENSE
  skills/peekaboo-control/
    SKILL.md
    references/
      operations.md
      setup.md
      troubleshooting.md
      validation.md
```

`SKILL.md` — короткий вход: триггер, выбор пути, основной цикл, границы
разрешений, ссылки по ситуации. Цель — до 500 слов, без копии справочника.
Описание начинается с `Use when` и описывает задачи macOS GUI/Peekaboo.
`operations.md` — компактная карта MCP/CLI по задачам и проверенные ловушки
версий. `setup.md` — инвентаризация, согласие, установка и подключение двух
клиентов. `troubleshooting.md` — различение transport, Bridge, TCC, policy,
sandbox, устаревших целей и clipboard. `validation.md` — безопасная живая
приёмка и границы доказательств. README описывает установку плагина и
отдельную настройку MCP. MIT LICENSE следует соседним плагинам.

Оба manifests содержат `name: peekaboo-control`, `version: 1.0.0`,
`skills: ./skills/`. В каждый marketplace добавить одну запись, сохранив
существующие; в корневом README добавить описание и команды установки.

## Проверка результата

Перед написанием скилла подготовить отложенные задачи и baseline без него:
готовый Mac; неполная установка; отказ foreground при всех TCC правах;
CLI-only операция; неизвестный исход клика; устаревшие IDs; отсутствующий
в сессии MCP при существующей конфигурации. Задачи и ответы не включать
как примеры в навык. После написания повторить их в свежих процессах
с новой версией скилла; смотреть реально прочитанный текст и решения.
Не давать оценщикам менять живое окружение или конфиги. Проход baseline
не выдавать за улучшение; неуспех новой версии исправить и перепроверить.

Проверить YAML, JSON manifests/marketplaces, уникальность имени,
существование ссылок и путей, сохранность соседних записей. Не добавлять
формальные unit-тесты, которые только повторяют текст документации.

Живую проверку проводит один агент: предупредить о тестовом окне,
использовать собственное временное окно приложения с полем ввода и
прокруткой. Через MCP подтвердить Desktop Bridge, права, наблюдение,
targeted click, ввод уникального тестового текста и прокрутку с проверкой
результата. Для CLI выполнить минимум одну дополнительную read-only
операцию и подтвердить поддержку каждой публикуемой команды через help;
действующие команды из справки проверять на своём окне при наличии grants.
Если действие запрещено MCP, зафиксировать ограничение и не обходить его.
Закрыть только своё окно, удалить только свои временные артефакты,
восстановить изменённое тестом состояние без вмешательства в чужую работу.

В публичный отчёт поместить версии, матрицу «проверено / заблокировано /
не проверено», выводы и команды с переносимыми placeholders. Не публиковать
личные пути, идентификаторы устройства, скриншоты, сырые логи, конфиги,
корпоративные адреса или секреты. Чистый второй Mac и полную установку
в Claude Code считать непроверенными, пока такого прогона не было.

После независимого ревью опубликовать обычным fast-forward в GitHub main,
не перезаписывая параллельные изменения. Установить скилл в Codex из
опубликованного SHA официальным skill-installer; не дублировать его
одновременно standalone и plugin установкой. Проверить `skills/list`
в собственном свежем app-server процессе. Если текущей сессии нужен
перезапуск для обнаружения навыка, явно сказать об этом.

## Основания и решения автора

Исследованный текущий контур: CLI 4.9.0, Desktop 4.9.5. Это свидетельство
совместимости конкретного прогона, не универсальный минимум версий.
Количество MCP tools не фиксируется: источники истины — текущие схемы
и локальный help. Известны расхождения `select_text`/`select-text`,
`set_value`/`set-value`; в CLI v4 нет старых `list` и `image` маршрутов.
Скриншот CLI — через поддерживаемый `see` согласно локальному help.

Выбор автора: один документационный плагин с четырьмя тематическими
справками, русским телом инструкций и английским trigger description;
без автоматического installer или runtime wrapper.
