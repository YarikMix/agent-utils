# Физический Android через Appium MCP

Статус: проект для согласования. Дата: 23.10.2026.

## Задача и результат

Пользователь подключил Samsung Galaxy A17 к Mac по USB. Нужно настроить управление
физическим телефоном через Appium MCP, установить локальные debug-сборки Облака и
Почты для будущей работы со стендами, затем оформить воспроизводимый опыт в два
самостоятельно устанавливаемых скилла: `android-control` и `setup-android-control`.
Конкретной прикладной задачи пока нет. Пользователь явно выбрал локальные debug,
а не публичные версии приложений.

Результат имеет три отдельно подтверждаемых части:

1. Подключённый MCP создаёт/переиспользует живую сессию именно физического Samsung.
2. Через MCP подтверждены PNG, XML, поиск элемента, нажатие, ввод и очистка своего
   текста, прокрутка, Back и Home. Исходное состояние безопасной пробы восстановлено.
3. На Samsung установлены локальные debug APK `ru.mail.cloud` и `ru.mail.mailapp`,
   каждое приложение запущено, показан его реальный экран. Готовность к будущим
   стендам означает наличие debug-сборок; вход и выбор конкретного стенда не входят.

Успешные `adb devices`, установка APK и `session create` по отдельности не доказывают
полное управление. Установка скиллов не означает подключение MCP.

## Границы

Основной поддерживаемый путь: macOS, физический Android, USB, официальный
`appium-mcp`, embedded UiAutomator2. Отдельный Appium HTTP server не требуется.
Две инструкции предназначены для Claude Code и Codex. Для других ОС не заявлять
проверенную настройку; поддержку эмулятора не включать в основной сценарий.

Не входят: root, изменение корпоративных политик телефона, беспроводная отладка,
вход в аккаунты, отправка почты, загрузка пользовательских файлов, настройка
конкретного минидева и развёртывание WebView/Chromedriver. Native/WebView contexts
нужно различать, но работа внутри WebView — отдельная задача.

Публикация PR/пуш не включены в эту задачу. Итоговые файлы и проверки готовятся
локально; установка двух готовых скиллов в локальные каталоги обнаружения клиентов
входит в результат. Не создавать дубликаты уже установленного плагина/скилла.

## Подтверждённое исходное состояние

Проверено 23.10.2026, до изменения окружения:

- ADB вне песочницы видит единственный подключённый Samsung SM-A175F, Android 16,
  API 36, состояние `device`. USB-отладка и доверие этому Mac уже работают.
- Приложения `ru.mail.cloud` и `ru.mail.mailapp` на телефоне не обнаружены.
- Appium MCP подключён к текущему Codex. Managed sessions отсутствуют.
- `select_device(platform="android")` возвращает `Neither ANDROID_HOME nor
  ANDROID_SDK_ROOT environment variable was exported`.
- На Mac уже есть Android SDK, platform-tools 37.0.1, Build-Tools 35.0.0/36.0.0,
  JDK 17/21/24. Нужный SDK не нужно скачивать заново.
- Установлены `appium-mcp` 1.97.1, `appium-uiautomator2-driver` 8.7.0,
  `appium-adb` 16.1.0, Node 24.21.0. Это найденная комбинация, ещё не свидетельство
  успешного управления Android.
- У существующей записи MCP уже есть iPhone-настройки: `NO_UI`,
  `CAPABILITIES_CONFIG`, command/args и timeout. Android SDK/JDK ей не переданы.
- В установленном MCP Android defaults включают `autoGrantPermissions: true`.
  Explicit capabilities перекрывают defaults и локальную конфигурацию.
- Локальный APK Облака `liveDebug` существует, `application-debuggable`,
  `ru.mail.cloud`, minSdk 26, targetSdk 36; внутри есть `arm64-v8a`,
  `armeabi-v7a`, `x86`, `x86_64`. Запуск на физическом телефоне пока не проверен.
  APK не новый; свежесть фиксируется
  при приёмке, пересборка нужна при технической несовместимости, а не автоматически.
- Готовый APK Почты в ожидаемом `mail-app/build/outputs/apk` не найден.
  Наличие в иных каталогах не исключено. При отсутствии подходящего APK нужна
  локальная сборка `mail_ruDebug` по `setup-mail-android`.

Исходники общих скиллов: GitHub `YarikMix/agent-utils`, `origin/main` на момент
подготовки `510fb17`. Основа — актуальные iPhone-плагины, включая их правила
владения устройством, контекстов, проверки ввода и восстановления состояния.
Работа ведётся в отдельном worktree; чужие ветки и правки не затрагиваются.

## Решение по окружению

Это предлагаемые технические решения автора, а не отдельные пожелания пользователя.

1. Сохранить существующую установку Appium MCP и iOS capabilities. Внести только
   необходимые значения Android SDK и `JAVA_HOME` в env записи Appium MCP реально
   используемого клиента. Предпочесть уже установленный JDK 17. Не менять глобальные
   shell-профили, launchctl и Gradle-конфигурацию ради подключения Android.
2. Перед изменением конфигурации сделать приватную резервную копию. Редактировать
   точечно, сохраняя комментарии и чужие записи. Не применять `codex mcp add/remove`,
   не печатать целиком конфиги и переменные окружения. Синтаксис проверить парсером.
3. Перезапустить именно MCP или клиент способом, реально доступным в этом хосте,
   учитывая принадлежащие ему сессии; текущий Android session list пуст.
   После перезапуска повторно проверить tools, discovery и живую сессию.
   Если перезапуск может сделать только человек — сообщить одно точное действие
   и продолжить независимую работу. До повторной проверки текущего подключённого
   сервера не заявлять, что MCP починен; отдельный диагностический процесс этого
   не доказывает.
4. В local embedded session не передавать выдуманный `remoteServerUrl`.
   Явно задать выбранный serial/UDID, `platformName: Android`,
   `automationName: UiAutomator2`, `noReset: true`, `fullReset: false`,
   `autoGrantPermissions: false`. Не запускать эмулятор ради физического телефона.
5. Предпочесть созданные сервером свободные порты; не фиксировать общий systemPort
   на несколько сессий. Не удалять чужую сессию и не запускать второй контроллер
   на том же телефоне.
6. Системные диалоги в пределах задачи обрабатывать по свежему экрану самостоятельно.
   Пароль/биометрию и вход в аккаунты выполняет человек. Samsung Auto Blocker,
   MDM или другой запрет установки сначала диагностировать; изменение защитной
   настройки, если оно потребуется, согласовать с пользователем явно.

## Установка локальных приложений

Использовать уже существующие специализированные `setup-cloud-android` и
`setup-mail-android`, если требуется сборка; не дублировать их подробности в новых
универсальных скиллах. Облако собирается с `CI=1`, Почта — без `CI`.

APK проверить по package ID, debuggable, ABI, minSdk и подписи. На выбранном Samsung
проверить наличие пакета и использовать установку с сохранением данных `-r -t`.
При несовместимой подписи не удалять приложение автоматически: удаление данных
выходит за рамки обычной установки и требует решения пользователя.
Все ADB-команды привязывать к выбранному serial; эмуляторы и другие телефоны
не затрагивать. ADB разрешён для диагностики, установки и точечных операций,
а доказательство пользовательского управления получить через Appium MCP.

Если подходящий APK Почты отсутствует, собрать локально существующий `mail_ruDebug`
без изменения исходников. Перед тяжёлой сборкой проверить память и активную IDE,
не убивать общие Gradle/Kotlin-демоны. Секретные `local.properties`, `.env*` и
credential-файлы не открывать. Не обновлять ветки приложений автоматически и
не переписывать их настройки только ради установки.

После установки активировать launcher activity, определённую по APK/установленному
пакету, и подтвердить экран каждого приложения PNG/XML. Не использовать случайный
launcher (у Облака есть LeakCanary). Проверить установленный debug-флаг; один
`Success` от установки недостаточен. Оставить приложения без авторизации.

## Структура двух плагинов

`plugins/android-control/`:

- `skills/android-control/SKILL.md` — короткий цикл управления готовым физическим
  телефоном, выбор/переиспользование сессии, единственный владелец, явный sessionId,
  свежие наблюдения и границы перехода в настройку.
- `references/operations.md` — реальные схемы подключённого MCP: PNG/XML, context,
  поиск по resource-id/accessibility id, tap, ввод/очистка, scroll, Back/Home,
  lifecycle, текущий package/activity и проверка физического serial.
- `references/recovery.md` — bounded retry после наблюдения, stale session,
  USB disconnect, утеря UiAutomator2 и диагностика без слепого повторения действий.
- `references/validation.md` — проверенные операции, версии и честные ограничения.

`plugins/setup-android-control/`:

- `skills/setup-android-control/SKILL.md` — начальная настройка и переход по точной
  ошибке; готовую машину не переустанавливать.
- `references/setup.md` — совместимость Node/JDK/SDK, официальный npm с lockfile,
  USB/debug/trust, discovery, конфигурация Codex/Claude Code, embedded session,
  самостоятельная живая приёмка и передача sessionId в `android-control`.
- `references/troubleshooting.md` — missing SDK/JAVA_HOME/adb, device unauthorized/
  offline, неверное устройство, Samsung install restriction, APK/signature/ABI,
  instrumentation/UiAutomator2 timeout, ограничения песочницы и необходимость
  перезапуска MCP после изменения env. Не придумывать универсальные обходы.

У каждого плагина README, MIT LICENSE, Claude/Codex manifests версии 1.0.0.
Зарегистрировать плагины в обоих marketplace-манифестах и корневом README по
существующему формату репозитория. Плагин с инструкциями не подключает MCP сам.
Связь между скиллами должна работать при установке любого из них отдельно:
локальная ссылка допустима только на свой reference; на второй плагин — имя
и публичный источник установки. Личные serial, абсолютные пути, аккаунты,
корпоративные URL/код/логи и кадры телефона в публичные файлы не включать.

## Рабочий цикл и приёмка

Перед пробой сохранить исходное приложение/activity, экран и context. На телефон
команды отправляет только один исполнитель. Для native локаторов сначала
проверить context, переключить на NATIVE_APP при необходимости, затем получить
новые PNG/XML. Нельзя определять реальное устройство по одному `deviceName`.

Для безопасной пробы использовать системные Настройки без изменения настроек:
наблюдение → найти элемент → tap → проверить переход → Back; затем поиск с
собственным уникальным текстом, проверка точного значения, очистка и проверка
пустоты; прокрутка с наблюдаемым смещением и возврат; Home. Точный маршрут зависит
от свежего интерфейса Samsung, не фиксируется по памяти или координатам iPhone.
Ввод на русском проверить отдельно, если инструмент позволяет; ограничения
зафиксировать без обещаний. Существующее чужое содержимое поля не стирать.

После пробы убрать только свой ввод и восстановить исходный экран Настроек,
исходное приложение и доступный исходный context, проверив PNG. При объективной
невозможности точно перечислить восстановленное и оставшееся состояние.
После установки приложений открыть каждое для подтверждения, затем вернуться
на исходный экран; собственную рабочую сессию оставить доступной для будущей
задачи и передать её ID пользователю локально.

Статическая проверка: валидные JSON и YAML frontmatter, зарегистрированы ровно
два новых плагина в обоих маркетплейсах, существуют все относительные ссылки,
отсутствуют секреты и локальные значения. Сценарная проверка инструкций покрывает
переиспользование готовой сессии, неоднозначный выбор телефона, missing SDK,
таймаут с неизвестным исходом, WEBVIEW перед native, сохранение пользовательского
текста и запрет удаления приложения при несовместимой подписи. Live smoke
проверяет поведение телефона; сценарии скилла не заменяют live smoke.

Отчёт должен раздельно перечислить установленное, реально проверенное,
непроверенное и требуемые действия человека. Чистая установка на втором Mac,
работа Windows/Linux и любые будущие версии зависимостей не считаются
подтверждёнными испытанием одного Samsung на этой машине.

## Что оставлено исполнителю

Выбрать точные команды реально зарегистрированных MCP tools, безопасный маршрут
в Samsung Settings, существующий подходящий APK либо способ его сборки, способ
локальной установки скиллов без дубликатов, разумные таймауты и проверки.
Дополнительные runtime/doctor-скрипты не требуются: основной артефакт — инструкции
на основании подтверждённой практики. Если для результата понадобится собственный
runtime, изменить дизайн и согласовать расширение до реализации.
