# setup-ios-sim: клавиатура и буфер обмена Simulator

## Назначение и объём

Переносимый скилл для Claude Code и Codex настраивает ввод с клавиатуры Mac и синхронизацию буфера обмена в iOS Simulator. Настройка глобальная для текущего пользователя macOS: распространяется на новые устройства и устраняет конфликтующие индивидуальные отключения у существующих. Запрос «проверь» выполняется без записи; запрос «настрой» разрешает описанные изменения.

Поставка — скилл `setup-ios-sim` внутри существующего плагина `phone-control` репозитория `YarikMix/agent-utils`. Версия плагина повышается до `1.1.0`; существующие скиллы управления физическими устройствами сохраняются. Установка плагина сама настройки не меняет. Xcode и нужный iOS runtime уже установлены. Скилл не собирает приложения, не устанавливает SDK, не настраивает физические iPhone и не управляет аккаунтами.

## Выбранный подход

1. **Выбран пользователем:** инструкции с командами macOS для настроек и Peekaboo для работающего Simulator. Без отдельного CLI, демона, hooks и новых зависимостей.
2. **Рассмотрен:** собственный CLI `check/apply`. Даёт единый программный интерфейс, но требует сопровождения кода; для текущего объёма не нужен.

Основной путь — штатные preferences macOS. Peekaboo дополняет его для состояния GUI, применения переключателей и проверки результата. Одно успешное выполнение `defaults write` не считается доказательством работающего ввода.

## Требуемое поведение

### 1. Диагностика окружения

- Определить используемый Xcode/Simulator и состояние приложения, не полагаясь только на глобальный `xcode-select`: он может указывать на Command Line Tools. Не менять глобальный developer selector.
- Учитывать действующие инструкции и профиль машины. Для Xcode на внешнем диске проверить ожидаемый mount и доступность до обращения к SDK; персональные пути, UUID и корпоративные зависимости в плагин не включать.
- Прочитать только относящиеся к задаче настройки домена `com.apple.iphonesimulator`. Показать глобальные значения и конфликтующие индивидуальные настройки отдельно. Отсутствующий ключ отличать от явно сохранённого `false`.
- Если нужно воздействовать на открытое окно, однозначно определить устройство/окно. Глобальная запись не требует выбора одного устройства; UI-проверка требует точной цели.

### 2. Глобальные настройки

| Настройка | Требуемое значение |
|---|---|
| `ConnectHardwareKeyboard` | Boolean `true` |
| `PasteboardAutomaticSync` | Boolean `true` |

- В `DevicePreferences` найти существующие явные `ConnectHardwareKeyboard = false` и установить `true`. Существующие `true` оставить; отсутствующие ключи не создавать. Остальные поля устройств и настройки Simulator сохранить.
- Не заменять весь домен или словарь устройств подготовленным шаблоном. Способ точечного изменения вложенных preferences должен быть проверен при реализации; неизвестный формат нельзя исправлять догадкой.
- После записи перечитать значения и подтвердить отсутствие явных индивидуальных отключений. Повторный запуск при правильных значениях ничего не переключает и не добавляет.
- Работающий Simulator может держать настройки в памяти и перезаписывать их. Скилл должен различать запись на диск и применение приложением, проверять сохранность изменений после штатного жизненного цикла и не обещать применение ко всем открытым окнам по одной записи.

### 3. Применение в работающем Simulator

- Перед UI-операциями использовать `peekaboo-control`, обнаружить актуальные инструменты, проверить права и выбранное приложение. Не обходить ограничения инструментов другим способом.
- Для точного окна проверить меню `I/O → Keyboard → Connect Hardware Keyboard`, `I/O → Input → Send Keyboard Input to Device` и `Edit → Automatically Sync Pasteboard`.
- Менять только подтверждённо выключенные пункты. Отсутствие признака галочки в текстовом выводе не доказывает выключенное состояние. При неизвестном состоянии получить дополнительное наблюдение, а не нажимать toggle вслепую.
- После действия повторно наблюдать состояние. Передачу клавиш через `Send Keyboard Input to Device` не объявлять глобально сохранённой настройкой без отдельного подтверждения её области действия и сохранности.
- `Toggle Software Keyboard` / `⌘K` управляет видимостью экранной клавиатуры; её скрытие не требуется для приёмки. Предпочтение раскладки пользователя автоматически не менять.
- Если для применения нужен перезапуск, объяснить последствия и учесть действующее разрешение пользователя. Не закрывать рабочие окна, не завершать процессы и не перезагружать устройства без соответствующей авторизации.
- Если Peekaboo отсутствует или нужная операция недоступна, дать точный ручной шаг и честно оставить UI-проверку незавершённой; автоматически устанавливать или перенастраивать Peekaboo не требуется.

### 4. Проверка ввода и буфера

- Проверить набор контрольного несекретного текста с клавиатуры Mac и вставку текста через `⌘V` в подходящее поле симулятора. Не использовать пароль, одноразовый код, отправку формы или поле с автосохранением пользовательских данных как тестовую цель.
- Для диагностики буфера читать только перечень доступных форматов. Пустой буфер и буфер с PNG/TIFF без текстового представления не считать поломкой синхронизации.
- Тестовый текст копирует пользователь либо используется разрешённый временный режим буфера с корректным восстановлением. Не печатать, сохранять в отчёт или пересылать исходное содержимое буфера. Не затирать более новую копию пользователя восстановлением старой.
- Если текст в буфере есть, но `⌘V` не работает, отдельно проверить фокус поля, передачу клавиш и доступность вставки внутри iOS. Не объявлять ошибку конкретной версии Xcode только по симптому.
- Проверить обратное направление синхронизации контрольным текстом из симулятора в безопасную цель на Mac. Если проверено только одно направление, указать это в результате.

## Сохранность и границы

Не сбрасывать настройки целиком, не стирать и не пересоздавать устройства, не трогать приложения и сессии входа. Не сбрасывать службы буфера и разрешения macOS ради первой попытки починки. Сохранённые глобальные значения, индивидуальные переопределения, состояние открытого окна и функциональная проверка — разные результаты; отчёт перечисляет только подтверждённые.

## Приёмка

1. Оба клиента могут обнаружить скилл через свои манифесты и каталог; имена, версии, пути и ссылки согласованы, YAML/JSON валидны.
2. Проверены сценарии отсутствующих глобальных ключей, глобального `false`, индивидуального `false`, уже правильных настроек и неизвестного формата. Режим проверки не пишет; посторонние настройки сохраняются; повторное применение ничего не меняет.
3. На реальном Mac подтверждены глобальные `true`, отсутствие конфликтующих переопределений, состояние выбранного окна, ввод с клавиатуры и вставка контрольного текста. Направления синхронизации проверены отдельно.
4. Сохранность подтверждена после разрешённого штатного перезапуска Simulator; проверено наследование устройством без индивидуального ключа. Без этих проверок не заявлять устойчивость после перезапуска или настройку всех устройств по умолчанию.
5. Сценарии «в буфере только изображение», «несколько открытых устройств», «Peekaboo недоступен» не приводят к ложному диагнозу, произвольному выбору окна или слепому переключению.
6. Проверки поведения выполняются по требованиям этой спецификации, а не только по наличию нужных фраз в тексте. Артефакты прогонов и ограничения приёмки хранятся локально вне спецификации.

## Технические неопределённости для проверки при реализации

Точный способ безопасной записи индивидуальных preferences, фактическое применение к работающему Simulator, получение состояния галочек доступной версией Peekaboo и сохранность режима передачи клавиш. Если наблюдения требуют изменить согласованное поведение, обновить эту спецификацию до реализации соответствующего изменения.
