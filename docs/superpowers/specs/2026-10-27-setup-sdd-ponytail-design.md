# Настройка глобальных инструкций для Superpowers SDD и Ponytail

Дата: 2026-10-27. Статус: согласовано пользователем переходом к writing-plans.

## Зачем

Добавить в публичный `YarikMix/agent-utils` скилл `setup-sdd-ponytail` для
Claude Code и Codex. Он настраивает глобальные инструкции так, чтобы Ponytail
упрощал реализацию по согласованной спецификации, сохраняя обязательный процесс
Superpowers SDD. PAIW поддерживается, но не является зависимостью.

## Подходы и выбор пользователя

1. Использовать существующую подключённую глобальную память; если её нет —
   небольшой блок в действующих глобальных инструкциях клиента. Меньше новых
   файлов, проще проследить загрузку. **Пользователь выбрал этот вариант.**
2. Всегда создавать отдельную общую заметку и подключать её из глобальных
   инструкций клиентов. Удобно для нескольких клиентов, но требует нового
   файла и отдельной проверки его подключения.

## Поведение скилла

1. Определить целевой клиент и действующий источник глобальных инструкций.
   Моё предложение по умолчанию: настраивать текущий клиент; другой или оба —
   если это входит в запрос. Не менять настройки второго клиента лишь потому,
   что он установлен.
2. Читать существующие инструкции и только относящиеся к задаче ссылки на
   память. Если уже подключена глобальная память, использовать её формат и
   индекс. Для PAIW это заметка и одна ссылка в `MEMORY.md`; наличие каталога
   само по себе не доказывает, что клиент читает эту память.
3. Без подключённой памяти использовать штатные глобальные инструкции.
   В Codex учитывать фактический `CODEX_HOME` (по умолчанию `~/.codex`) и
   приоритет непустого `AGENTS.override.md` над `AGENTS.md`. В Claude Code
   использовать пользовательский `~/.claude/CLAUDE.md` с учётом фактического
   каталога конфигурации клиента. Память отдельного репозитория не считать
   глобальной. Не создавать override ради этой настройки.
4. Найти существующее правило по смыслу и содержимому. Полное совместимое
   правило оставить без изменений; неполное дополнить на месте. Новое добавить
   компактным разделом. Сохранить чужие инструкции, формат и ссылки; не
   переписывать файл целиком. Для симлинка проверить фактическое назначение;
   управляемый или недоступный для записи источник не обходить созданием
   затеняющего файла, а сообщить ограничение.
5. Запрос настройки разрешает необходимые изменения в своей области без
   повторного согласования. Запрос только проверки или объяснения — чтение и
   рекомендации. Установка плагина сама по себе ничего не записывает в память.
   Реальный конфликт существующих пользовательских правил требует уточнения;
   не отменять их молча.
6. После настройки перечитать изменённые участки, проверить отсутствие дублей
   правила/индексной ссылки и показать пути и краткое содержание изменений.
   Объяснить, что обновлённые глобальные инструкции проверяют в новой сессии.

## Содержимое правила

Базовый абзац хранится без изменения формулировки:

> При работе по Superpowers SDD сохраняй обязательные этапы, артефакты, согласования, тестирование и ревью. Ponytail применяй для выбора простейшей реализации, полностью выполняющей согласованную спецификацию. Упрощение не должно сокращать требования или обходить этапы SDD.

К нему добавляются два указания:

- При совместном использовании Ponytail и Superpowers SDD ведущий агент
  вставляет базовый абзац дословно в стартовые задания исполнителю и ревьюеру,
  а также в каждое задание исправления, включая продолжение прежнего субагента.
  Вместе передаёт пути к согласованным спецификации и плану. Одна ссылка на
  память не заменяет полный текст правила.
- Принимать результат по требованиям согласованной спецификации и
  доказательствам обязательных проверок. Пропуски возвращать в существующий
  цикл исправлений SDD, без отдельного дополнительного ревью или нового цикла.

Правило действует при совместном использовании этих инструментов, учитывает
обычную иерархию инструкций и не вводит SDD для всех остальных задач.

## Границы

Моё предложение: поставлять инструкции без исполняемого установщика, новых
хуков и зависимостей. Не изменять исходники, кэш или шаблоны Ponytail и
Superpowers. Не устанавливать отсутствующие плагины: сообщать, если настройка
памяти подготовлена, но активное использование обоих инструментов не
подтверждено. Не добавлять автоматический запуск настройки при старте сессии.

Наличие текста и самоотчёт агента не доказывают соблюдения правила. Скилл не
обещает гарантированную совместимость и не запускает большой SDD-прогон при
каждой настройке.

## Поставка

Отдельный плагин `plugins/setup-sdd-ponytail/`: один
`skills/setup-sdd-ponytail/SKILL.md`, manifests Claude Code и Codex, README и
лицензия по образцу соседних плагинов. Добавить плагин в оба marketplace и
корневой README. Обычная обнаружимость скилла сохраняется; описание должно
относиться к настройке интеграции, а не перехватывать обычные задачи SDD.
В публичных файлах не должно быть личных путей, содержимого памяти пользователя
или данных его окружения; согласованный общий текст правила является частью
поставки.

## Проверка и приёмка

- Проверить manifests, структуру, ссылки и frontmatter скилла.
- На изолированных сценариях проверить выбор действующего файла Codex при
  override/custom home; Claude Code без PAIW; подключённую память с частичной
  записью; повторную настройку; запрос только проверки. Проверять реальные
  изменения файлов и сохранность соседнего текста.
- Для поведенческой проверки скилла заранее подготовить отложенные случаи,
  снять исходный результат до правки и повторить после неё в свежих процессах.
  Не менять настоящую память пользователя ради испытания и не смешивать
  примеры из текста скилла с отложенными заданиями.
- Разделять результат записи, подтверждение загрузки в новом клиенте и
  наблюдаемое выполнение SDD. Недоступные проверки указывать отдельно;
  самоотчёт субагента не выдавать за доказательство текста отправленного задания.

Мелкие решения о структуре текста и изоляции испытаний остаются исполнителю.
