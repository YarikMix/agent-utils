# Setup Bash + ble.sh для Ubuntu в WSL

Дата: 2026-10-23. Статус: утверждено пользователем для планирования и реализации.

## Назначение

Добавить в `YarikMix/agent-utils` плагин `setup-bash-blesh` с одним скиллом для
Codex и Claude Code. Разработчик вызывает его вручную один раз, чтобы получить
проверенную настройку интерактивного Bash в Ubuntu под WSL. Скилл сначала
исследует фактическую среду и предлагает точный набор изменений; вызов ради
проверки сам по себе не переписывает конфиги. Если пользователь в том же запросе
уже явно поручил настройку, это разрешение действует без повторного вопроса.

Результат: подсветка ввода, автоматические предложения из истории и дополнений,
обычное Bash completion, принятие видимой серой подсказки клавишей Tab и
нейтральное отображение ещё не дописанных команд без красной заливки. Оболочкой
остаётся Bash; `ble.sh` — его интерактивное дополнение. Неинтерактивные
Bash-скрипты не должны зависеть от `ble.sh`.

## Вызов и проверка среды

- Скилл предназначен для явного запуска разработчиком; описание и инструкции
  не должны предлагать фоновую или автоматическую настройку при каждом сеансе.
- Проверить Ubuntu через `/etc/os-release`, WSL через доступные локальные
  признаки ядра/окружения, наличие Bash и фактические файлы текущего
  пользователя. Текущая оболочка агента не обязана быть Bash: агент может
  работать отдельным процессом, а Bash запускается в терминале.
- Наличие VS Code, `TERM_PROGRAM=vscode` или живого VS Code terminal не является
  условием для основной настройки. Если Ubuntu/WSL не подтверждены, сообщить
  причину и остановиться без изменений.
- Прочитать существующие `.bashrc`, `.blerc` либо фактический XDG-конфиг
  `ble.sh`, установку `ble.sh` и настройки удалённого VS Code, если они есть.
  Различать готовую, частичную и отсутствующую настройку. При повторном запуске
  не дублировать строки и не переустанавливать работающее дополнение без
  конкретной причины.
- До изменений показать конкретно недостающие шаги и их область действия.
  Сохранять пользовательские алиасы, PATH, комментарии и соседние настройки.
  При конфликтующей пользовательской привязке/теме объяснить замену до правки.

## Настройка Bash и ble.sh

Плагин содержит инструкции для агента, а не универсальный скрипт, который
переписывает пользовательские файлы. Агент выбирает актуальный официальный
способ установки `ble.sh` для текущего Bash/Ubuntu, фиксирует источник и
версию, проверяет необходимые инструменты и устанавливает только после
разрешения на предложенные изменения. Не выполнять непроверенный `curl | bash`.
Если установка или права недоступны, сообщить конкретный блокер. Работать в
домашнем каталоге текущего пользователя, не менять глобальную login shell
через `chsh` и не удалять `fish`/`zsh` или чужие пакеты.

Подключить `ble.sh` в `.bashrc` только после проверки интерактивности:
`source -- "$HOME/.local/share/blesh/ble.sh" --attach=none` после guard и
`[[ ! ${BLE_VERSION-} ]] || ble-attach` после пользовательских настроек в конце
файла. Пути определяются по фактической установке, приведённые команды —
проверенный для текущей сессии пример. Если структура `.bashrc` отличается,
адаптировать размещение, сохранив порядок настроек. Править точечно и держать
приватную резервную копию до проверки результата.

В `.blerc` или существующем файле инициализации `ble.sh` установить
`ble-bind -m auto_complete -f C-i auto_complete/insert` и аналогичную
привязку `TAB`. Они принимают видимое предложение, а без предложения Tab
сохраняет обычное completion. Установить `ble-face -s syntax_error none`,
чтобы частичная команда не получала красный фон. Это также убирает красное
выделение остальных синтаксических ошибок; агент сообщает об этом эффекте.
Другие цвета и настройки пользователя не менять.

## VS Code как дополнительный шаг

Если доступна конфигурация именно удалённого окна VS Code в Ubuntu/WSL,
проверить профиль терминала Linux. При выбранной другой оболочке отдельно
предложить сделать Bash профилем новых терминалов. Если VS Code не найден,
основной результат остаётся достижимым без этого шага. Не путать remote
settings Ubuntu с локальными Windows settings, не использовать присутствие
`vscode-server` как доказательство активного терминала данного окна.

При согласии обновить только нужные ключи профиля/дефолта, сохранив остальные
настройки и комментарии JSONC. Не завершать уже запущенные терминалы и
Codex/Claude сессии; новый профиль применяется к новым вкладкам. Скилл не
обещает исправлять неисправность UI VS Code, например неработающую кнопку
корзины: это отдельная проблема клиента.

## Проверка результата

1. Проверить синтаксис отредактированных shell-файлов и корректность настроек
   VS Code, если они менялись. Не печатать целиком пользовательские конфиги.
2. Запустить новый **интерактивный Bash в PTY** и подтвердить загрузку
   `ble.sh`, сохранение существующих пользовательских команд/путей и отсутствие
   загрузки в неинтерактивном Bash.
3. На безопасной синтетической истории проверить появление предложения,
   принятие его Tab без выполнения команды, обычное completion без видимого
   предложения и отсутствие красной заливки у частичного имени команды.
   Проверять фактическое поведение терминала, а не только наличие строк в
   конфиге.
4. Если изменялся VS Code, проверить целевые ключи удалённых настроек и
   объяснить, что для живой UI-проверки нужна новая вкладка. При отсутствии
   доступа к UI не выдавать чтение settings за подтверждение его поведения.
5. При сбое восстановить сделанные правки либо сообщить оставшееся состояние
   и точный следующий шаг. Итоговый отчёт отделяет проверенные факты от
   непроверенной интеграции.

## Состав плагина и границы поставки

```text
plugins/setup-bash-blesh/
  .codex-plugin/plugin.json
  .claude-plugin/plugin.json
  README.md
  LICENSE
  skills/setup-bash-blesh/
    SKILL.md
    references/setup.md
    references/validation.md
```

Короткий `SKILL.md` описывает ручной триггер, границы, входную проверку и
ссылки на пошаговую настройку/проверку. Версия плагина `1.0.0`; добавить его в
оба marketplace и корневой README по образцу соседних плагинов. Плагин не
содержит исполняемого установщика, MCP-сервера или фонового сервиса. Нельзя
включать в него личные пути, содержимое истории, токены или данные локальной
машины. В README объяснить, что установка плагина добавляет инструкции, а
настройка Bash выполняется только после явного вызова.

Проверить структуру/manifest/ссылки, идемпотентность на готовой системе,
сценарии частичной конфигурации и неподходящей ОС, а также живой путь в Codex.
Claude Code в текущей среде недоступен для живой проверки: упаковку и команды
вызова сверить с существующими общими плагинами, ограничение явно сообщить.

## Решения, оставленные исполнителю

Исполнитель выбирает конкретный актуальный официальный релиз/ревизию `ble.sh`
и безопасный метод точечной правки пользовательских файлов после проверки их
содержимого. Он же выбирает небольшие тестовые сценарии и механизм изоляции
проверочной HOME/PTY, сохраняя приведённое поведение и ограничения.
