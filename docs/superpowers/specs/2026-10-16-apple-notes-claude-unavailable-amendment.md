# Уточнение приёмки Apple Notes: Claude Code без аккаунта

Пользователь сообщил, что сейчас аккаунта Claude Code нет, и согласовал
продолжение реализации и живой проверки Codex с сохранением существующей
поддержки Claude и явно неподтверждённой новой живой проверкой Claude.

Это дополнение имеет приоритет над требованием двух успешных живых клиентов в
[дизайне](2026-10-15-apple-notes-claude-codex-design.md) и
[плане](../plans/2026-10-15-apple-notes-claude-codex.md).
Исторические документы не переписываются. Остальные требования сохраняются.

## Изменение обязательного gate

Task 1 допускает продолжение после положительных реальных контрактов Codex
0.162.1 и их независимого ревью. Они получены в `4212963`; scoped review не
обнаружил новых дефектов. Результат прежнего двухклиентского verifier остаётся
неуспешным: недостающий Claude не становится положительным отчётом.

Claude auth blocker и неснятые события становятся отложенной живой проверкой,
а не блокировкой Tasks 2–8. Нельзя создавать фиктивные успешные raw-события или
называть Claude live-проверенным. При появлении рабочего аккаунта первоначальный
Claude probe и соответствующие сценарии приёмки остаются обязательными перед
заявлением о проверенной новой интеграции Claude.

## Требования к реализации и проверкам

- Один сервер, семь инструментов, независимые настройки папки, существующие
  Claude userConfig, команды, ограничения заметок и shell guard сохраняются.
- Требование картинок только из пользовательских вложений текущего диалога
  действует в обоих клиентах. Прежнее разрешение всего Claude tmp/scratchpad
  не возвращается. Исходные сохранённые байты обязательны, неизвестное
  происхождение отклоняется до записи.
- Codex adapter строится по реальным событиям Task 1. Для Claude можно
  реализовать структурный adapter по доступным реальным данным и документированным
  формам, с автоматическими положительными/отрицательными проверками. Тестовые
  примеры ненаблюдавшихся форм явно обозначаются как synthetic/documented;
  они не подменяют неполную реальную fixture и не доказывают host-контракт.
- Не отключать все картинки Claude безусловно ради прохождения тестов.
  Поддержанные формы сохранённых пользовательских inline bytes должны работать;
  неизвестная форма безопасно отклоняет картинку и сохраняет текстовые операции.
- Отсутствие аккаунта не мешает проверить сборку, MCP-протокол обоих host,
  независимость конфигурации, прежние ограничения Notes, манифесты и доступные
  проверки установки Claude без model call. Эти проверки выполнить.

## Изменения исполнения плана

- Task 1: закрыть gate для продолжения по Codex и этому согласованному
  дополнению; Claude live остаётся явно отложенным, не PASS.
- Task 3: вместо требования двух полноценных реальных fixtures использовать
  реальную Codex fixture, доступную неполную Claude fixture и отдельно
  обозначенные структурные Claude cases; не угадывать неизвестное как факт.
- Tasks 5–7: реализовать обе упаковки/адаптеры и автоматические проверки,
  опираясь на тот же уровень доказательств. Настоящий Codex probe остаётся
  основанием namespace, hook rewrite и Code Mode.
- Task 8: выполнить server-only проверки обоих host и доступную полную живую
  матрицу Codex. Model/setup/image-сценарии Claude отметить NOT RUN — нет аккаунта.
  Общий двухклиентский PASS не заявлять. Точное обнаружение скилла/хука и
  local-marketplace отличать от Git source, как в первоначальном плане.
- Публикацию ветки, merge и изменение действующей пользовательской установки
  этим дополнением не разрешаем; подготовить проверяемый результат в worktree.
  Git-source сценарии до разрешённой доставки отмечаются NOT RUN.

Итог разработки может быть готов к публикации с полностью проверенным Codex и
перечисленными ограничениями проверки Claude/Git source. Это не равнозначно
первоначальной полной приёмке обоих клиентов.
