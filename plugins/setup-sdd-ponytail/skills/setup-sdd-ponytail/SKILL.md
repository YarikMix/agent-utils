# Настройка Superpowers SDD и Ponytail

Сохрани правило в подключённой глобальной памяти, иначе — в действующих глобальных инструкциях клиента. PAIW поддерживается, но не является зависимостью. Этот скилл относится к настройке интеграции; обычная задача SDD сама по себе не требует настройки.

## Выбери источник

1. По умолчанию целевой клиент — текущий. Другой или оба клиента настраивай только в пределах запроса. Наличие второго клиента не разрешает менять его настройки.
2. Определи фактический каталог конфигурации из контекста запуска или адресно проверь только нужную переменную; не печатай всё окружение и не читай секреты.

| Клиент | Действующий пользовательский источник |
|---|---|
| Codex | `$CODEX_HOME` или, если он не задан, `~/.codex`. Используй **непустой** `AGENTS.override.md`; при его отсутствии или пустом содержимом — `AGENTS.md`. Пустой override оставь пустым; не создавай override ради настройки. |
| Claude Code | `CLAUDE.md` в фактическом каталоге `CLAUDE_CONFIG_DIR`, по умолчанию `~/.claude/CLAUDE.md`. Учитывай перенос каталога, а не второй файл в стандартном месте. |

3. Прочитай действующий файл и относящиеся к задаче ссылки на память. Считай память глобальной, только если инструкции клиента действительно подключают её для разных проектов. Наличие каталога PAIW не доказывает подключения; память репозитория, включая обычную auto memory Claude Code, не является глобальной.
4. Для подключённой глобальной памяти соблюдай её формат и индекс. В PAIW используй существующую заметку о правиле либо создай заметку и одну ссылку в `MEMORY.md`. Сам файл инструкций при этом не дублируй правилом. Без подключённой памяти помести компактный раздел в действующий пользовательский файл; отсутствующий штатный файл можно создать. Каталоги PAIW для этого не нужны.

## Внеси только недостающее

Запрос настройки разрешает необходимые записи в своей области без повторного согласования. «Только проверь» или объяснение означают чтение и рекомендации, без записи.

Перед записью проверь назначение симлинков и ограничения источника. Управляемый или недоступный файл не меняй и не обходи новым override, fallback-файлом или копией: сообщи конкретное ограничение. При явном конфликте пользовательских правил остановись до записи и уточни, какое правило пользователь хочет сохранить; запрос общей настройки не разрешает молча отменять конфликтующее правило.

Найди существующую запись по смыслу и содержимому. Полная совместимая запись с дословным базовым абзацем и обоими указаниями ниже требует **нулевого diff**, в том числе в индексе. Частичную дополни на месте только недостающим. Сохраняй соседний текст, формат и ссылки; не переписывай файл целиком. Повторная настройка не создаёт вторую заметку, раздел или индексную ссылку.

### Сохраняемое правило

Базовый абзац вставляй дословно:

> При работе по Superpowers SDD сохраняй обязательные этапы, артефакты, согласования, тестирование и ревью. Ponytail применяй для выбора простейшей реализации, полностью выполняющей согласованную спецификацию. Упрощение не должно сокращать требования или обходить этапы SDD.

Добавь к нему оба указания:

- При совместном использовании Ponytail и Superpowers SDD ведущий агент вставляет базовый абзац дословно в стартовые задания исполнителю и ревьюеру, а также в каждое задание исправления, включая продолжение прежнего субагента. Вместе передаёт пути к согласованным спецификации и плану. Одна ссылка на память не заменяет полный текст правила.
- Принимать результат по требованиям согласованной спецификации и доказательствам обязательных проверок. Пропуски возвращать в существующий цикл исправлений SDD, без отдельного дополнительного ревью или нового цикла.

При создании записи укажи, что правило действует при совместном использовании этих инструментов, учитывает обычную иерархию инструкций и не вводит SDD для остальных задач. Для уже полной записи это пояснение дай в отчёте без изменения файлов.

## Проверь и сообщи результат

Перечитай изменённые участки и сравни diff с областью запроса: только выбранный источник, сохранный соседний текст, точный базовый абзац, оба указания, отсутствие дублей правила и ссылки в индексе. Для полной настройки и повторного запуска проверь нулевой diff.

Не изменяй исходники, кэш или шаблоны Ponytail и Superpowers, не устанавливай отсутствующие плагины, не добавляй хуки или автозапуск настройки. Если использование обоих плагинов не подтверждено, сообщи: запись подготовлена, активное совместное использование не подтверждено.

Разделяй три результата:

| Уровень | Доказательство |
|---|---|
| Запись | Перечитанный текст, пути и diff. Покажи краткое содержание изменений либо причину отсутствия записи. |
| Загрузка | Отдельная проверка действующего источника в **новой сессии** клиента. Запись файла и чтение этого скилла такой проверкой не являются. |
| Выполнение SDD | Наблюдаемые задания и проверки: дословная передача правила, пути спецификации и плана, приёмка по доказательствам в существующем цикле исправлений. Самоотчёт агента не доказывает содержание отправленного задания. |

Укажи непроверенные уровни. Не обещай гарантированную совместимость и не запускай большой SDD-прогон при каждой настройке.
