# Peekaboo Control

Основной путь — Peekaboo MCP → работающий Desktop Bridge. Это документационный навык: его установка сама не подключает MCP.

## Выбери инструмент

Для браузера или приложения с подходящим специализированным инструментом используй его. Для физического iPhone используй доступный `iphone-control` ([публичный навык](https://github.com/YarikMix/agent-utils/tree/main/plugins/iphone-control/skills/iphone-control)); управление симулятором этим навыком не заменяется.

Обнаружь инструменты текущей сессии и прочитай актуальные схемы нужных операций. На готовом Mac проверь соединение и права через фактический MCP; не начинай с установки или обновления. Desktop — host Bridge, не второй MCP-сервер. Подключение должно явно задавать локальный socket; автовыбор host не доказывает Desktop.

## Рабочий цикл

Свежее наблюдение конкретного окна → одно действие → проверка смыслового результата. Передавай opaque IDs буквально вместе со свежей целью; после изменения состояния наблюдай заново. Для ожидания проверяемого состояния предпочитай доступный `verify_state`. Timeout и неизвестный исход требуют нового наблюдения до любого повтора.

CLI дополняет отсутствующую MCP-операцию, иной документированный режим или диагностику. Перед использованием читай актуальный leaf `--help`, проверяй цель и результат. Отказ политики MCP не разрешает обход через CLI.

## Полномочия

Screen Recording, Accessibility и Event Synthesizing — системные разрешения, отдельно от политики MCP. Даже при всех TCC grants сервер по умолчанию background-only. Foreground и temporary clipboard — отдельные grants процесса сервера. Если действие требует grant, назови конкретный блокер и запроси явное разрешение пользователя; уже данную авторизацию учитывай. Не включай grants незаметно.

На другом Mac сначала проведи read-only инвентаризацию. Разрешение на установку/настройку запрашивай только для недостающих компонентов. Системные диалоги подтверждает человек. Не ослабляй TLS, подпись приложения или macOS security.

Clipboard используй лишь в рамках задачи и разрешённого режима. Временный режим должен восстановить прежнее содержимое только пока владеет своей записью, сохраняя более новую копию пользователя. Для диагностики соединения содержимое clipboard не читай.
