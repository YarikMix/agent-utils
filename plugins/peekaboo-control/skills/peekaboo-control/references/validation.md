# Приёмка и границы доказательств

## Безопасная живая проверка

Один агент проводит GUI приёмку. Предупреди, что появится собственное временное окно с полем ввода и прокруткой. Убедись, что это твоё окно; не используй чужой документ или ввод пользователя.

1. Зафиксируй версии CLI/Desktop, актуальные MCP schemas, явное подключение к Desktop socket и его host identity. Получи права через фактический MCP; диагностика CLI с явным socket дополняет, но не заменяет его.
2. Получи свежее наблюдение собственного exact window. Через MCP выполни targeted click, введи уникальный тестовый текст, прокрути область. Между действиями обновляй цель и проверяй смысловой результат; для подходящих состояний используй `verify_state`.
3. Если MCP отказывает по policy, запиши блокер. Отдельный CLI путь для обхода этого отказа не используй. Если grant нужен, объясни конкретное разрешение; учти уже данное согласие.
4. Для CLI выполни минимум одну дополнительную read-only операцию, например explicit-socket Bridge status из [operations](operations.md). Каждую публикуемую команду проверь через leaf help. Живые mutation формы проверяй лишь на собственном окне при достаточных grants; иначе отметь непроверенными.
5. Закрой только собственное окно, удали только свои временные артефакты. Восстанови изменённое тестом состояние, сохранив более новые пользовательские изменения; проверь transactional clipboard cleanup, если он использовался.

## Отчёт

Для каждой проверки укажи **проверено / заблокировано / не проверено**, результат и предел вывода. Разделяй catalog/help, успешный transport/host handshake, права ОС, grants policy, dispatch и наблюдённый эффект действия. Leaf help доказывает поддержку синтаксиса, не live mutation. Sandbox denial не доказывает TCC denial.

В публичном отчёте оставляй версии, выводы и команды с переносимыми placeholders. Не публикуй личные пути, идентификаторы устройства/процесса, screenshots, сырые логи, конфиги, корпоративные адреса и секреты. Приватные доказательства держи вне публикуемых файлов.

Чистый второй Mac, установка недостающего и полный путь Claude Code считаются непроверенными без отдельного фактического прогона. Совместимая пара версий не устанавливает универсальный минимум.

Для проверки самого навыка используй отложенные задачи до/после текста, свежие процессы и trace реального чтения нового SKILL.md/нужных references. Ответы тестов не публикуй как примеры. Baseline pass не называй улучшением; auth/startup failure клиента не оценивай как решение задачи.
