# Диагностика по подтверждённому блокеру

Сначала прочитай точную ошибку и нужный фрагмент лога без секретов. `xcodebuild code 65` — итоговый код, конкретную причину ищи выше: signing, trust, XCTest, build configuration. Не лечи любую ошибку переустановкой npm, не удаляй пользовательские приложения/профили/чужие сессии.

| Наблюдение | Проверка и следующий шаг |
|---|---|
| Скилл есть, Appium tools нет | Установка скилла и MCP независимы. Проверь только свою config запись, абсолютные пути Node/entry, env NO_UI/CAPABILITIES_CONFIG и статус запуска сервера; перезапусти клиент и заново обнаружь схемы. Не пересоздавай все настройки. |
| MCP не стартует / engine warning | Проверь Node по абсолютному executable из config и engines обоих пакетов: для проверенной комбинации `^22.12.0 || >=24.0.0`, npm >=10. Версия интерактивного shell может отличаться от GUI. |
| Телефон не обнаружен | Кабель/USB, разблокировка и Trust, Devices and Simulators, выбранный полный Xcode. Подтверждения делает человек. Выясни, не выбран ли simulator; не меняй UDID угадыванием. |
| Несколько real устройств / неверный телефон | Согласуй выбор с человеком, сверь фактический UDID и `iosDeviceType:real`; проверь override caps файла/hint/call. До выбора не отправляй ввод. Simulator в deviceName может быть default, не свидетельство типа. |
| Unsupported OS / device unavailable / build destination | Сверь macOS–Xcode–iOS по Apple и Xcode Devices. Установи поддерживаемый Xcode/компоненты; если это недоступно, сообщи совместимость как блокер, не обещай обход переустановкой MCP. |
| No profiles / signing / expired / revoked | Собственный Account/Team, доступный Apple Development certificate и подходящий WDA identifier/profile; Automatic signing и registration capability. Истёк Personal Team — renewal в Xcode и новый driver build/install. Чужой app-specific profile не используй. См. setup §4. |
| Developer App not trusted | Человек доверяет своему Developer App в VPN и управление устройством; может требоваться сеть для валидации. Не вводи код/Apple Account за человека. |
| Developer Mode disabled | Человек включает Developer Mode и завершает требуемую перезагрузку/подтверждение. |
| WDA/XCTest timeout, UI Automation off или ожидается запрос | Человек включает Настройки → Разработчик → Автоматизация интерфейса и физически разблокирует iPhone; доступное подтверждение XCTest агент обрабатывает самостоятельно по свежим PNG/XML. Если нужен код/пароль или Face ID — его выполняет человек. При наблюдаемом сценарии с Mirroring — закрывает Mirroring. После подтверждения повтори запуск, учитывая предыдущий исход. Не считай увеличение timeout исправлением отказа подписи или отсутствия подтверждения. |
| Managed session есть, screenshot → socket hang up | Список не проверяет liveness WDA. Проверь устройство/соединение/лог и ownership. При доказанно stale собственной сессии заверши только её и создай новую с тем же проверенным устройством/caps. Чужую не удаляй; согласуй дальнейшую работу с владельцем/пользователем. Не переустанавливай рабочий MCP. |
| Timeout после tap/input, исход неизвестен | Получи свежее наблюдение до решения о повторе; не дублируй ввод вслепую. Сетевой сбой не доказывает, что действие не произошло. |

Отчёт о блокере: этап → точная ошибка → подтверждённые проверки → конкретное действие человека/следующий шаг → что ещё не проверено. Статус «готово» допустим только после PNG/XML и подтверждённой навигации на согласованном физическом iPhone.
