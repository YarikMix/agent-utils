# Физический iPhone через Appium MCP

Используй официальный Appium MCP и embedded XCUITest driver с подписанным WDA. Для симулятора выбери соответствующий навык. Системные диалоги в пределах порученной задачи обрабатывай самостоятельно по свежим PNG/XML: для нажатия их кнопок отдельное подтверждение пользователя не требуется. Код-пароль, Face ID и вход в Apple Account выполняет человек.

## Начало работы

1. Узнай зарегистрированные tools и их актуальные схемы, затем прочитай managed sessions (`appium_session_management`, `action:list`). Не начинай готовый Mac с переустановки.
2. Сверь целевой физический iPhone и UDID с выбором пользователя и установи единственного владельца управления. До любых действий, включая создание своей сессии, убедись, что телефон свободен от другого исполнителя. Подходящую сессию переиспользуй: выбери её и передавай `sessionId` явно. Сессия не даёт права управлять чужим телефоном. При нескольких телефонах без выбора спроси пользователя; уже согласованный телефон повторно выбирать не нужно. `deviceName: iPhone Simulator` может быть неверным default: проверяй фактический UDID и тип устройства, не отвергай сессию только по имени.
3. Перед native наблюдением и локаторами прочитай `appium_context({action:"list",sessionId:S})`; если текущий context не `NATIVE_APP`, переключи `appium_context({action:"switch",context:"NATIVE_APP",sessionId:S})`. Затем получи свежие PNG/XML, старые element IDs не используй. `select` не переключает context.
4. Если подходящей сессии нет, обнаружь **real** iOS device, подтверди выбор и создай local embedded session по [операциям](references/operations.md). Не готовь симулятор и не выдумывай localhost URL. Remote допустим только с URL от пользователя.

## Передача управления

Перед делегированием проверь доступ **самого исполнителя** к нужным MCP tools: наличие у controller этого не доказывает. Передай устройство, `sessionId`, context, исходный экран, разрешённые действия и явный способ возврата владения. Пока владеет worker, controller и наблюдатели не отправляют телефону команды, включая наблюдение. Без tools worker анализирует уже снятые безопасные артефакты, а controller остаётся исполнителем. Верни владение явно перед следующим действием другого агента.

## Рабочий цикл

Получи свежие PNG и XML, открой PNG и выбери цель по наблюдению. Предпочитай accessibility id, затем платформенный селектор; координаты — запасной путь. Уменьшенный PNG не задаёт координаты устройства: проверь размеры окна, поворот и масштаб. Выполни одно действие, получи новое наблюдение и проверь смысловой результат. Успех tool означает доставку, а не достижение цели. При таймауте или неизвестном исходе сначала наблюдай, затем решай о повторе; не повторяй вслепую.

Для замены текста/URL сначала очисти разрешённое поле и проверь пустоту, затем введи полный текст и подтверди точное значение **до** отдельного Go/Return — [operations](references/operations.md). Там же описаны PNG/XML, locator/tap, жесты, lifecycle, Home и уровни доказательства открытия, включая StoreKit. При stale driver, повторном Code 41 или недостающей операции читай [recovery](references/recovery.md): только своё владение, один ограниченный retry, диагностический WDA после проверки привязки; запрет policy нельзя обходить.

Границы живой проверки — в [validation](references/validation.md). Береги пользовательские данные; после приёмочной пробы убери только свой тестовый текст и восстанови исходное приложение. Сохрани исходный context пробы и восстанови его, если он ещё доступен и соответствует исходной задаче; не вмешивайся в чужую параллельную работу. Не удаляй чужую сессию; завершай только собственную, когда это не мешает задаче.

## Когда нужна настройка

Отсутствует MCP/tool, устройство недоступно, WDA/подпись/Developer Mode/XCTest дают конкретный блокер — переходи к `setup-iphone-control`, передав точную ошибку. Скилл может быть установлен поштучно: если его нет, используй [источник и установку setup-iphone-control](https://github.com/YarikMix/agent-utils/tree/main/plugins/setup-iphone-control/skills/setup-iphone-control), а не отсутствующий соседний файл. Установка плагина описана в README его каталога. Установка скилла сама по себе не подключает MCP. Переустановка не исправляет любой таймаут: сначала установи причину.
