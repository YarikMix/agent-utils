# apple-notes-folder

MCP-сервер Apple Notes для Claude Code и Codex. Семь инструментов работают
**только с одной явно выбранной папкой**; подпапки не входят в её границу.
Настройки клиентов независимы.

## Требования

- macOS с приложением «Заметки».
- Node.js 20 или новее, доступный в `PATH` как `node`.

## Установка и настройка

```sh
claude plugin marketplace add YarikMix/agent-utils
claude plugin install apple-notes-folder@yarikmix-plugins

codex plugin marketplace add YarikMix/agent-utils
codex plugin add apple-notes-folder@yarikmix-plugins
```

Добавление каталога не устанавливает плагин. Установка использует готовые
`dist/server.js`, `dist/hook.js` и `dist/configure.js`, без npm/build.

В Claude Code задайте папку при установке или через
`/plugin configure apple-notes-folder@yarikmix-plugins`. Сохраняется обязательный
параметр `folder`, передаваемый серверу как `NOTES_FOLDER`.

В Codex вызовите `$apple-notes-folder:setup` и явно выберите точное имя одной
папки. Скилл найдёт bundled `dist/configure.js` внутри установленного плагина,
проверит папку и запишет `$CODEX_HOME/agent-utils/apple-notes-folder/config.json`
(по умолчанию `~/.codex/agent-utils/apple-notes-folder/config.json`). Затем
перезапустите MCP-сервер или сессию Codex. Значение `NOTES_FOLDER` в Codex не
используется; конфигурацию клиента вручную менять не требуется.

Имя — точно как в боковой панели Заметок. Для папки по умолчанию используйте
скриптовое имя `Notes` (даже если интерфейс показывает «Заметки»). Если папки нет
или имя неоднозначно, настройка отклоняется; папку плагин не создаёт.

При первом обращении macOS может спросить разрешение терминалу управлять
«Заметками». Полный доступ к диску не нужен. В Codex подтвердите доверие только
просмотренным хукам Apple Notes штатным интерфейсом клиента.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `notes_list` | заметки папки: id, заголовок, дата изменения; новые сверху; `limit` 1–200 (по умолчанию 50), `offset` ≥ 0 |
| `notes_search` | поиск по заголовку и тексту внутри папки, без учёта регистра; `limit` 1–50 (по умолчанию 20) |
| `notes_read` | заметка целиком в Markdown; ответ длиннее 200 000 символов обрезается с пометкой в конце; картинки — заглушками `![картинка N](note-image:N)`; если у заметки есть вложения, в конце — строка «[Вложений в заметке: N — их содержимое сервер не показывает]» |
| `notes_create` | новая заметка: заголовок и текст в Markdown, можно с картинками |
| `notes_append` | дописать Markdown в конец, можно с картинками; у заметки с вложениями или списками — отказ |
| `notes_update` | заменить текст целиком, можно с картинками; у заметки с вложениями или списками — отказ; заметку, прочитанную с обрезкой, целиком не заменить (используйте `notes_append`) |
| `notes_delete` | удалить; заметка уходит в «Недавно удалённые» |

`notes_append` и `notes_update` сохраняют текст, но оформление, которого нет в Markdown (подчёркивание,
цвета, шрифты), может стать обычным текстом — это ограничение конвертера Markdown ↔ HTML, а не порядок
обхода. Заметки со списками (в том числе чек-листами) эти два инструмента вообще не трогают — см. «Списки
и чек-листы» ниже.

## Картинки

В версии **2.0.0** принимаются только подтверждённые пользовательские вложения
**текущего диалога**. Хуки связывают вложение с сообщением и сохраняют исходные
байты; сервер использует закрытый снимок и одноразовый допуск сроком 15 минут.
Неизвестное происхождение, произвольный файл и scratchpad отклоняются до записи.
Путь `localImage.path` без сохранённых байтов сообщения не даёт разрешения.

Для `notes_create`, `notes_append`, `notes_update` используйте Markdown-ссылку
на вложение, которую предоставляет хук. Секретный `attachment_ticket` добавляет
хук, его не нужно составлять вручную. Формат определяется по сигнатуре:
PNG, JPEG, GIF, HEIC, WebP; размер до 10 МБ. Заметки копируют проверенный снимок
как вложение через `file://`. Снимки хранятся до 24 часов; активная операция
сохраняет свой снимок до завершения.

**После первой картинки сервер текст этой заметки не меняет.** Любое изменение текста через скрипты портит
вложения заметки: картинки становятся битыми плашками «Файл» или пропадают. Поэтому `notes_append` и
`notes_update` у заметки с вложениями (картинками, файлами — в том числе добавленными вручную) отвечают
отказом и ничего не пишут. Такую заметку можно читать и удалять. Ещё картинки и новый текст — в новую заметку.
Отдельного инструмента «добавить вложение» нет: у Заметок такая команда показывает каждую картинку дважды.

## Списки и чек-листы

Заметки отдают чек-лист скриптам как обычный маркированный список `<ul><li>…</li></ul>` — без признака
чек-листа и без отметок; эти данные есть только во внутренней базе Заметок, а её чтение требует полного
доступа к диску, от которого плагин отказался. Запись текста превратила бы чек-листы в обычные списки и
стёрла бы отметки, поэтому `notes_append` и `notes_update` заранее отказывают, если в теле заметки есть
`<ul` или `<ol` (любой список может быть чек-листом) — такую заметку можно только читать и удалять, новый
текст пишите в новую заметку. Список можно добавить в новую заметку (`notes_create`) или дописать в заметку
без списков — но после этого заметка для правки закрыта. Так же поступает `sweetrb/apple-notes-mcp` без
полного доступа к диску: запрещает правку целиком.

## Границы и что сервер не защищает

- Папка ищется по имени при старте, дальше сервер работает с ней по id. Если папок с таким именем несколько
  (например, в разных аккаунтах) или ни одной — инструменты отвечают ошибкой настройки. Папку «Недавно
  удалённые» (и её локализованные варианты) указать нельзя — в ней вперемешку лежат удалённые заметки всех
  папок.
- Каждое действие с заметкой по id сначала проверяет, что заметка лежит в разрешённой папке. Подпапки в
  границу не входят. Заметки под паролем не читаются и не меняются.
- Данные не подставляются в текст скриптов: всё передаётся аргументами и временным файлом.
- Сервер не делает сетевых запросов.
- **Разрешение macOS выдаётся терминалу целиком.** Любая программа из этого терминала может управлять
  Заметками в обход сервера. Плагин ставит хук (`PreToolUse`: Claude `Bash`/`Monitor`, Codex canonical `Bash`, включая Code Mode),
  который отклоняет команды, где скриптовый запускатель (`osascript`, AppleScript, JXA, ScriptingBridge)
  встречается вместе с именем «Заметок» в виде строки в кавычках (`"Notes"`, `'Notes'`, с необязательным
  путём перед именем и `.app` после — `"/System/Applications/Notes.app"`), bundle id `com.apple.Notes` или
  `NoteStore`, а также отдельно — `sqlite3` вместе с `NoteStore`. Скрипт в отдельном файле, зашифрованную
  строку или запуск через другой язык хук не поймает — это защита от случайного обхода, не от намеренного.
  - Хук может отклонить и безобидную команду, где оба признака совпали случайно — например, `grep osascript
    x.log | grep "Notes"`.
  - Если терминалу дать ещё и полный доступ к диску (Full Disk Access), инструменты агента (Read, Grep) смогут
    прочитать базу Заметок напрямую, в обход и сервера, и хука — плагин от этого не защищает. Не выдавайте
    терминалу полный доступ к диску.
  - Картинка сверяется с сохранёнными байтами пользовательского сообщения и публикуется как закрытый
    снимок; поздняя подмена исходного пути не разрешает новые байты.
- Удаление и замену текста лучше не добавлять в автоматически разрешённые инструменты.

## Проверка сборки

`dist/` закоммичен, чтобы плагин работал без установки зависимостей. Чтобы убедиться, что он собран ровно
из исходников и `package-lock.json`:

```bash
cd plugins/apple-notes-folder
npm ci && npm run verify-build
```
