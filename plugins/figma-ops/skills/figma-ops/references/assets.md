# Экспорт, image fills, замеры и QR

Используй поддерживаемый MCP-экспорт, если он даёт требуемый файл. Если текущая схема/выдача не обеспечивает результат, настроенный REST даёт `export`/`fills`; [auth](auth.md). Ограничения отдельного MCP не распространяй на все инструменты. UI fallback нужен, когда доступные MCP/REST результата не дают.

```sh
python3 "$FIGMA_OPS_CLI" export SyntheticKey --node '1:2' --node '1:3' --format png --scale 2 --dest '/tmp/figma assets'
python3 "$FIGMA_OPS_CLI" fills SyntheticKey --node '1:2'
python3 "$FIGMA_OPS_CLI" fills SyntheticKey --node '1:2' --dest '/tmp/figma sources'
```

`export`: нода из URL или повторные `--node`, 1..20 nodes, PNG/JPG/SVG/PDF, scale 0.01..4 (default 1). REST запрашивает `contents_only=true`. Null render/ошибка скачивания/невалидные bytes — per-node failure: все failed → error, смешанный успех → partial. URL рендера ещё не готовый экспорт: ссылки скачиваются сразу, токен не передаётся на asset host. HTTPS only; запрещён downgrade redirect на HTTP.

Файлы публикуются атомарно под безопасными именами из node ID. Существующий файл не меняется без `--overwrite`; используй новый dest, если перезапись не поручена. Проверяются PNG/JPG/PDF signatures, SVG XML. У файла path,bytes,format,width/height,alpha,scale_requested; поля могут быть null. Для PNG `transparent` означает реально найденный пиксель с alpha ниже максимума для его глубины, `opaque` — непрозрачно. Для других форматов прозрачность не обещается.

PNG в export и fills ограничен 100 000 000 пикселей и 8 MiB несжатых samples на строку (без filter byte; зависит от глубины и числа каналов). До 64 MiB декодированных scanlines включительно проверяются реальные пиксели нечересстрочного PNG, включая 16-bit. Более крупные PNG сохраняются после потоковой проверки CRC, полного zlib stream, длин строк и filter bytes; пиксели не реконструируются, `alpha=unknown` с явным warning. Это бюджет анализа, а не предел размера сохраняемого файла: RGBA8 4096×4096 и RGBA16 такого размера поддерживаются. Для Adam7 alpha всегда unknown с предупреждением. Повреждённые/обрезанные streams и выход за пределы dimensions отклоняются; SVG ограничен 64 MiB, неподдерживаемые XML-кодировки дают per-asset error.

`fills` собирает imageRef из fills/backgrounds/strokes **выбранного поддерева**; dependency-ноды вне него не входят. Без dest возвращает refs/URLs, с dest скачивает источники без перерендера. Сверь coverage, missing refs и warnings. Это API image-fill source, не гарантия исходных uploaded bytes. GIF87a/GIF89a и RIFF/WEBP поддерживаются как fills sources по сигнатурам; alpha unknown с предупреждением (GIF dimensions из header, WebP dimensions nullable).

## Проверить готовый ассет

Для обещания «прозрачный PNG 2×» нужны точная нода, геометрия/экспортные границы, реальные размеры и реально прозрачные пиксели. `scale_requested=2` означает запрос, не доказательство: API может downscale. Проверяй совпадение width/height с ожидаемым 2× от source bounds, соответствие изображения screenshot и отсутствие фона канваса/соседей/обрезанных деталей. При неизвестных bounds точный 2× не подтверждён. Наличие alpha-канала и расширение PNG не доказывают прозрачность; `opaque`/`unknown` нельзя выдать за готовый прозрачный ассет. Не меняй заливки, маски или дизайн ради прозрачности.

Ранее конкретный MCP `download_assets` запекал фон канваса даже с `defaultScale:2`, а `get_screenshot contentsOnly:true` давал прозрачный 1× независимо от maxDimension. Эти наблюдения полезны для диагностики, но сегодняшнюю схему и фактический файл проверяй заново. Скриншот окна, локальный апскейл 1×, RGB 2× с альфой 1× и пересборка rawImages по координатам не являются экспортом исходной композиции: маски/наложения расходятся.

UI fallback по `peekaboo-control`: свежим наблюдением проверь выбранную точную ноду, Export PNG 2× и настройки фона, сохрани в каталог задачи, проверь bytes/размеры/alpha. Сохрани исходные UI-настройки и восстанови свои изменения, не затирая новые действия пользователя. Если корректный результат получить нельзя, укажи непрошедшие проверки и недостающий материал.

## Замеры и исходные растры

Для долей пикселя нужен масштабный экспорт 3–4× с подтверждёнными размерами, измерение видимых краёв, одинаковые области и реальные scale. Натуральный/уменьшенный screenshot не даёт нужной точности. Фон для измерения допустим, если файл не выдаётся за прозрачный production asset. Повороты проверяй по рендеру, не x/y дерева.

Для посадки текста выдели одинаковый box и одну полосу строчных букв. Посчитай плотность тёмных пикселей по строкам; выбери длинный непрерывный run (выносные элементы отдельно), midpoint `(top+bottom+1)/2`; переведи px в координаты макета через подтверждённый scale и сравни с центром box. Покажи выбранный run: произвольный порог/другая строка дадут ложное смещение. Для цветов используй свойства fill/style макета, не пипетку сглаженного скриншота.

Вставленный скриншот приложения может быть уменьшен внутри frame. Детали/production source бери из MCP rawImages или CLI fills, проверяя фактический источник. Масштаб для замера определи по элементу известного размера; отношение ширин кадров ошибочно при разных viewport. Учитывай JPEG-сжатие. Исторический MCP ограничивал rawImages/svgAssets по 20 на вызов — сверяй сегодняшние лимиты и truncation, за конкретной картинкой запрашивай меньшую ноду.

## QR

Сначала возьми качественный экспорт/источник. Если текущий браузер поддерживает BarcodeDetector:

```js
const image = document.querySelector('img');
await image.decode();
const codes = await new BarcodeDetector({formats: ['qr_code']}).detect(image);
// codes: rawValue и boundingBox — сопоставь каждый код месту на макете.
```

При нераспознавании попробуй canvas 2×/4× с `imageSmoothingEnabled=false`. Новых данных это не создаёт, но помогает детектору. Декодер возвращает фактическую строку либо не распознаёт код; не дописывай ожидаемый суффикс вручную. На полном кадре может быть несколько QR: сверяй boundingBox. CLI не содержит QR-декодер; используй доступный инструмент без автоматической установки зависимостей.
