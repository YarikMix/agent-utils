# Отключение скилла в Codex

Отключи конкретный скилл через пользовательский конфиг Codex. Это полное отключение: скилл перестаёт предлагаться в автокомплите и автоматически выбираться агентом. Установленные файлы остаются на месте.

## Определи цель

Возьми точное имя из доступного каталога скиллов. У плагинного скилла сохраняй префикс `plugin:skill`; у обычного — его имя. Заголовок интерфейса и имя папки могут отличаться от имени в каталоге.

На скриншоте ориентируйся на явно выбранную строку. Если имя обрезано, сопоставь видимую часть с каталогом и контекстом. Когда подходят несколько скиллов и выбор неясен, задай один вопрос с кандидатами и дождись ответа. Само упоминание скилла без просьбы отключить его не означает разрешения на правку.

## Измени конфиг

Цель — `config.toml` в `CODEX_HOME`, если эта переменная задана, иначе `~/.codex/config.toml`. Читай только нужную переменную окружения. Конфиг может содержать секреты: разбирай его в памяти, выводи только относящиеся к цели поля `name`, `path`, `enabled`.

В Codex 0.162.1 проверено отключение по точному имени, в том числе для скиллов встроенных плагинов:

```toml
[[skills.config]]
name = "plugin:skill"
enabled = false
```

1. Прочитай и разбери исходный TOML. Если он некорректен, сообщи об ошибке и не перезаписывай его.
2. Найди существующие записи `skills.config` для цели: по точному `name` либо по `path` к этому скиллу, учитывая симлинки и путь к папке или `SKILL.md`. Сохрани исходный способ адресации и установи `enabled = false` в совпавших записях. Если они уже отключены, оставь файл без изменений.
3. Если совпадений нет, добавь одну запись по имени, как выше. Не создавай дубликат при повторной просьбе. Учитывай границы TOML-таблиц, в том числе вложенных: поле должно относиться именно к выбранной записи.
4. Правь исходный текст точечно, сохраняя остальные настройки, комментарии и форматирование. Не сериализуй весь TOML заново. Не меняй флаг всего плагина, кэш или `SKILL.md`: это другие действия, а правку кэша обновление плагина может затереть.
5. Перед записью разбери получившийся TOML и сравни с исходным: изменились только записи выбранного скилла. После записи прочитай файл заново и проверь сохранённые значения. Существующие отключения других скиллов должны сохраниться.

Явной просьбы отключить однозначно определённый скилл достаточно для этой правки; повторное согласование не нужно. Если запись требует разрешения песочницы, используй штатный механизм разрешений.

## Подтверди результат

Ответь кратко: точное имя, ссылка на конфиг, результат проверки и необходимость перезапустить Codex для обновления автокомплита. При повторном вызове сообщи, что скилл уже отключён.

Сохранённый `enabled = false` подтверждает настройку на диске. Если доступна проверка каталога Codex с перечитыванием настроек, сверь состояние там; иначе не утверждай, что текущая сессия уже обновила подсказки. Если после перезапуска скилл остаётся виден, проверь версию Codex, активный `CODEX_HOME`, проектные переопределения и фактическое имя в каталоге.
