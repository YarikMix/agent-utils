# Figma: чтение макетов

Скилл про то, как найти нужное в чужом большом файле макетов и не соврать по результату. Механика вызовов у MCP своя, здесь — что эти вызовы отдают, чего не отдают и как из этого не сделать ложный вывод.

Имена инструментов и параметры ниже относятся к проверенному MCP-пути. Перед вызовом сверь текущий каталог и схемы: доступные возможности зависят от сервера. Примеры нод и экранов условные.

## Опционально: peekaboo-control

Основной путь — Figma MCP: поиск, дерево узлов, свойства, размеры, скриншоты и поддерживаемый экспорт. Только для следующих задач, если нужного результата не даёт подключённый MCP, проверь доступность навыка `peekaboo-control`: просмотр стрелок между экранами на канвасе, настоящий прозрачный экспорт PNG в 2× и чтение комментариев с ответами и контекстом на макете. Для обычного чтения макетов не загружай его и не проверяй окружение Peekaboo.

Если навык доступен, прочитай его и поручай ему управление окном Figma, проверку Desktop Bridge, настройку и необходимые разрешения по его правилам. Уже данную авторизацию учитывай. Отказ MCP policy не обходи через CLI. Если навыка нет, настройка не разрешена или UI-путь заблокирован, сохрани ручной путь из соответствующего раздела; установка зависимости не обязательна. [Источник peekaboo-control](https://github.com/YarikMix/agent-utils/tree/main/plugins/peekaboo-control/skills/peekaboo-control).

Работай с точным файлом, страницей и нодой по исходной ссылке/node ID, а не только по имени окна. Перед UI-шагами зафиксируй исходные выбор, масштаб и параметры экспорта; после действия проверяй результат по свежему наблюдению. Не меняй содержимое макета ради просмотра или экспорта. После работы восстанови изменённые тобой параметры, если это не затрёт более новые действия пользователя. При неизвестном исходе сначала наблюдай состояние, а не повторяй действие.

## Главное: связи между экранами не видны в дереве узлов

`get_metadata` возвращает дерево узлов: тип, id, имя, координаты, размеры, вложенность. `get_design_context` возвращает вёрстку узла с `data-node-id` и скриншот. **В проверенных выдачах этих вызовов нет коннекторов между фреймами и прототипных переходов.** Возможности подключённого MCP сверяй с актуальными схемами; это ограничение проверенного пути, а не всех возможных инструментов Figma.

Отсюда правило:

> Из того, что в метаданных не видно перехода, **не следует**, что перехода нет. Это отсутствие сигнала в источнике, который такой сигнал не передаёт.

Формулировки вида «кейс макетом не покрыт», «адресат кнопки не определён», «стрелки нет» по выдаче этих двух инструментов делать нельзя. Максимум вывода по этим данным: «в дереве узлов перехода не видно, нужна отдельная визуальная проверка».

**Просмотр канваса.** Для визуальной проверки нужна читаемая область с обоими фреймами и линией между ними. Скриншот одного фрейма её не покажет — линия за границей кадра. Скриншот большой секции тоже может уменьшиться до нечитаемости: например, у секции порядка 18000×6400. Если подключённый MCP не даёт нужную область, используй доступный `peekaboo-control`: открой точный файл и страницу, приблизь и перемести вид канваса, проследи линию от одного экрана до другого и проверь наконечник. Если линия не помещается, осмотри её последовательными перекрывающимися участками; не угадывай связь по соседству фреймов. Сохрани читаемое визуальное подтверждение. Нарисованная стрелка сама по себе не доказывает прототипный переход. При недоступном UI-пути попроси человека показать нужный кусок; отсутствие связи в метаданных по-прежнему не доказывает её отсутствия на канвасе.

## Комментарии: полная ветка и контекст

Сверь текущий каталог MCP: если есть доступный инструмент чтения комментариев, предпочитай его. Дерево нод и рендер узла сами по себе не дают историю обсуждения. Если полная ветка уже предоставлена текстом или читаемыми скриншотами и её контекст ясен, разбери эти материалы без повторного открытия Figma.

Если нужно получить обсуждение из интерфейса, используй опциональный `peekaboo-control` по правилам выше:

1. Сверь файл и страницу. Открой нужный comment pin или запись в панели комментариев. Превью при наведении с многоточием и счётчиком replies не считай полной веткой.
2. Раскрой исходное сообщение и все ответы выбранной ветки. При необходимости прокрути её с перекрытием участков и сверь доступный счётчик ответов. Не делай вывод по первой реплике, пока ответы не прочитаны; непрочитанное или обрезанное отметь явно.
3. Зафиксируй порядок реплик, авторов и время в том виде, как оно показано. Не выдумывай точную дату из относительной подписи. Покажи, к какому месту макета относится pin; не приписывай соседней ноде комментарий и не выдумывай node ID, если привязка не подтверждена.
4. В выводе разделяй сообщение о договорённости, новое предложение и открытый вопрос, указывая автора. Поздний ответ сам по себе не отменяет прежнюю договорённость и не утверждает альтернативу. Статус resolved не заменяет чтение содержания. Не обещай полноту всех комментариев файла по одной ветке или текущему фильтру панели.

Этот сценарий — чтение: не отправляй ответы или реакции, не редактируй и не удаляй сообщения, не закрывай ветку через Resolve/галочку. Для выхода закрой только UI-панель; восстанови изменённый тобой режим просмотра/фильтр, если это не затрёт новые действия пользователя.

При недоступном UI-пути попроси полный текст ветки либо читаемые скриншоты с ответами, авторами, временем и контекстом pin. У Figma есть отдельный [REST API комментариев](https://developers.figma.com/docs/rest-api/comments-endpoints/) с правом `file_comments:read`; не подключай его и не ищи токены автоматически ради этой задачи.

## Ссылка из Figma часто указывает на слой, а не на экран

Когда человек выделяет модалку и копирует ссылку, в неё может попасть **подложка**, а не фрейм экрана. Например, ссылка на слой `Fade` 375×812 ведёт к затемнению внутри нужного фрейма.

Симптом: `get_metadata` по ноде отдаёт одинокий прямоугольник, `get_screenshot` — пустое затемнение. Это не доказательство отсутствия экрана.

**Резолвить предков.** Если пришедшая нода — `Fade`, `rounded-rectangle`, `vector` или инстанс без содержимого, найди нужный объект выше по дереву страницы. Предков можно восстановить по отступам в `get_metadata` (рецепт ниже).

## Как искать экран

**Имена текстовых узлов часто равны самому тексту — пока слой не переименован.** Поиск по фразе из копирайта — быстрый первый шаг. Но внутри компонентов и инстансов абзацы могут называться `Title`, а кнопки — `label`; фраза может найтись только в заметке дизайнера на канвасе.

**Второй заход — смысловые имена фреймов.** Для текста «Повторить проверку» ищи также «Ошибка доступа», «Нет соединения», «Повторная попытка». Найденная одноимённая кнопка другого экрана не доказывает, что нужного экрана нет.

**Третий заход — номера нод в репозитории задачи.** Разработчики оставляют их в документации и комментариях кода. Ищи через `git grep -nE '[0-9]{1,6}[:-][0-9]{3,6}'` и отдельно по `node-id=`. Не ограничивай поиск каталогом `src/`, если структура проекта неизвестна. Пустой поиск по фразе — ещё не «в макете этого нет».

## Инстансы и повёрнутые группы

Два похожих случая требуют разных действий: пустой вложенный инстанс внутри уже найденного объекта (кнопка, HUD) — это не подложка, тут нужен составной id вглубь (см. ниже); нода, пришедшая по ссылке, чей скриншот — не то, что просили (подложка, затемнение), — другой случай, тут объект выше по дереву, резолвить предков (раздел «Ссылка из Figma…» выше).

**Вложенные инстансы могут приходить без детей; их id бери из выдачи как есть.** Чтобы заглянуть глубже, запроси составной id из выдачи родителя: `I<инстанс>;<узел>`, например `I101:200;301:400`; на большей глубине цепочка удлиняется: `I101:200;301:400;501:600`. Не обрезай префикс и части после `;`. В проверенном дереве координаты были относительно родителя; абсолютное положение получается суммой по цепочке только с учётом трансформаций.

**`x`/`y` повёрнутого узла — не левый верхний угол видимой картинки.** Поворот может не попасть в выдачу. Декор, чёрточки и стрелки мерь по экспорту, а расхождение дерева с картинкой считай поводом проверить трансформацию.

**`svgAssets` дают размер экспортированного вектора.** Сравнивай его с ассетом в репозитории и размером в CSS; визуальный масштаб нельзя выводить только из положения узла.

## Размер выдачи и формат

`get_metadata` по странице флоу — **около 3 МБ**, в контекст не помещается и уходит в файл. Работать грепом по файлу, а не чтением.

**Ловушка формата:** имена в выдаче экранированы, в файле лежит `name=\"...\"`, а не `name="..."`. Наивный `grep 'name="'` даёт ноль совпадений и выглядит как «ничего не нашлось». Матчить с учётом обратного слэша. Сама выдача в файле — JSON-массив `[{type, text}]`: экранированные кавычки видны, пока читаешь файл как текст. Если загрузить его через `json.load` и склеить поля `text`, кавычки станут обычными, и регэксп пишется уже без обратного слэша — а переводы строк тоже становятся настоящими, и `split('\n')` вместо `split('\\n')`.

**Не ограничивай длину имени в регэкспе.** Имя текстового узла может быть целым абзацем; лимит вроде `{0,80}` молча теряет длинные узлы. ID должен допускать составные значения инстансов, например `I101:200;301:400`, а не только цифры и двоеточия.

Рецепт разбора с предками:

```python
open_re = re.compile(r'^(\s*)<(\w[\w-]*) id=\\"([^"\\]+)\\" name=\\"([^"\\]*)\\"')
stack = []
for ln in text.split('\\n'):
    m = open_re.match(ln)
    if not m:
        continue
    indent, tag, nid, name = len(m.group(1)), m.group(2), m.group(3), m.group(4)
    while stack and stack[-1][0] >= indent:
        stack.pop()
    if nid == TARGET:
        for s in stack:            # предки от корня к родителю
            print(s[1], s[2], s[3])
    stack.append((indent, tag, nid, name))
```

`get_design_context` — **дорогой**: на одном экране 375×812 выдачу обрезало по лимиту в 25000 токенов. Вызывать его только когда действительно нужна вёрстка узла, а не чтобы «посмотреть, что там». Для «посмотреть» есть `get_screenshot`.

Если инструмент запрашивает решение по Code Connect, следуй его актуальной схеме и правилам подключённого навыка; не выбирай ответ за пользователя. Для обычного чтения этот дорогой путь не нужен.

## Растровые ассеты: как достать картинку и прочитать, что на ней

Иногда мало посмотреть — надо разобрать содержимое: QR, штрихкод, мелкий текст на скриншоте. Тогда картинку надо вытащить из Figma и открыть в браузере.

**Если `get_screenshot` отдаёт короткоживущий URL,** скачай файл до истечения ссылки. В проверенном окружении прямая навигация браузера на такой адрес завершалась `net::ERR_ABORTED`. Для canvas/декодирования можно скачать картинку в каталог задачи, поднять локальный сервер и открыть `http://127.0.0.1:<порт>/<файл>`: так изображение same-origin. После работы останови свой сервер.

**В проверенном пути `get_screenshot` не увеличивал узел выше натурального размера.** `maxDimension` только уменьшал: запрос большого размера для узла 176×48 возвращал 176×48. Сверяй `width`/`height` с `original_width`/`original_height` и текущей схемой инструмента. Увеличение растра само по себе не добавляет исходных деталей.

**Для замеров — `download_assets` с `defaultScale`.** Когда нужны доли пикселя — где стоит текст в кнопке, зазор до соседа, края видимой части иконки, — бери экспорт `download_assets` с `defaultScale: 3–4`: кнопка 176×48 при `defaultScale: 4` приходит 704×192. В проверенном пути экспорт был непрозрачным, с запечённым фоном канваса (см. раздел про экспорт ниже), но для замера это не мешает: файл не идёт в репозиторий, и запрет «не выдавать за ассет» здесь не срабатывает. Мерь по видимым пикселям. Сниппет ниже рассчитан на одну строку текста и box без иконок:

```python
from PIL import Image

def text_band_center(path, scale, box, is_text):
    """Центр полосы строчных букв в box=(x0, y0, x1, y1) в px макета относительно
    центра box; > 0 — ниже центра. is_text(r, g, b) -> True для пикселя текста."""
    im = Image.open(path).convert('RGB')
    x0, y0, x1, y1 = (round(v * scale) for v in box)
    rows = [sum(is_text(*im.getpixel((x, y))) for x in range(x0, x1)) for y in range(y0, y1)]
    dense = [i for i, n in enumerate(rows) if n > 0.2 * max(rows)]   # строчные 0.55–1.0 от максимума, выносные ≤0.14
    if not dense:
        raise ValueError('ни одного пикселя текста — проверь is_text и box')
    runs, start = [], dense[0]
    for a, b in zip(dense, dense[1:] + [None]):
        if b != a + 1:
            runs.append((start, a)); start = b
    print('runs:', runs)  # видно, какая полоса выбрана
    top, bottom = max(runs, key=lambda r: r[1] - r[0])                # самая длинная полоса — строчные
    return (top + bottom + 1) / 2 / scale - (y1 - y0) / 2 / scale

# Пример: кнопка 176×48, defaultScale=4, область тёмного текста
text_band_center('button.png', 4, (33, 0, 125, 48), lambda r, g, b: r < 90 and g < 110)
```

При сравнении с вёрсткой измеряй ту же полосу текста и тот же box: положительное смещение означает положение ниже центра.

**Скриншоты приложения внутри макета — бери исходник из `rawImages`.** Вставленный в узкий фрейм растр может быть уменьшен. Если `download_assets` возвращает исходник, используй его для разбора деталей. Масштаб для замеров считай по элементу известного размера; отношение ширин кадров может быть неверным, если скриншот снят на другом viewport. Учитывай погрешность сжатия.

**Лимиты `download_assets` сверяй с текущим инструментом.** В проверенном пути выдача ограничивалась 20 `rawImages` и 20 `svgAssets` на вызов; лишнее обрезалось с сообщением, хотя сам экспорт приходил. За конкретной картинкой обращайся к меньшей ноде.

**Разбор QR** — например, браузерным `BarcodeDetector`, если он доступен в текущем браузере:

```js
const det = new BarcodeDetector({ formats: ['qr_code'] });
const img = document.querySelector('img');
await img.decode();
const res = await det.detect(img);      // res[0].rawValue
```

Не распозналось — перерисуй на canvas с масштабом 2 и 4 при `imageSmoothingEnabled = false`. Информации это не добавляет, но детектору иногда помогает. На полном кадре страницы вернутся все коды сразу, с `boundingBox` — по координатам понятно, какой левый, а какой правый.

**Как трактовать.** У QR контрольная сумма: декодер либо отдаёт точное содержимое, либо ничего. Значение, похожее на ожидаемое, но короче — это не сбой чтения, а то, что реально закодировано. Не дописывай ожидаемый суффикс вручную.

## Прозрачный экспорт 2×: ограничение MCP и UI-путь

В проверенном MCP-пути `download_assets` запекал в экспорт окружение канваса, включая фон под узлом. Одинаково непрозрачными оказались обычный экспорт, экспорт с `defaultScale: 2` и экспорт дочерней ноды; параметра «только содержимое» в той схеме не было. Это наблюдение о конкретном пути, а не запрет возможностей других серверов.

`get_screenshot` с `contentsOnly: true` в том же пути давал прозрачность, но оставался в натуральном размере: узел 375×404 при `maxDimension: 808` возвращался 375×404. Сверяй реальный размер результата и альфа-канал, а не только параметры запроса.

Отсюда ограничение проверенного MCP-пути: **прозрачный ассет в 2x этими вызовами
не получить**. Если доступен `peekaboo-control`, сделай настоящий экспорт через интерфейс
Figma: по свежему наблюдению проверь выбранную ноду, найди её Export, выбери PNG и масштаб
2×, проверь настройки фона и сохрани файл в каталог задачи. Не меняй заливки, маски или
содержимое макета для создания прозрачности и не перезаписывай чужой файл. Если цель или
настройки неоднозначны, сначала уточни их.

Проверь сохранённый PNG: ожидаемые размеры 2× по геометрии/экспортным границам ноды,
реальную прозрачность пикселей в альфа-канале и соответствие нужному узлу без фона канваса,
соседних объектов или обрезанных деталей. Сам формат PNG и наличие альфа-канала прозрачности
не доказывают. Если исходная нода непрозрачна или результат не прошёл проверку, не выдавай
экспорт за готовый прозрачный ассет. При недоступном UI-пути попроси человека экспортировать
и передать файл. Скриншот окна не заменяет экспорт, локальный апскейл 1× не даёт настоящий 2×.

**Обходы, которые кажутся рабочими, но портят ассет.** Свести композицию из `rawImages`
(исходные картинки со своей альфой) плюс координаты из `get_metadata` — это пересборка
дизайна руками: маски и наложения могут разойтись с исходным рендером. Склеить альфу из 1x-рендера с RGB из 2x-экспорта — та же ловушка. В обоих случаях
получается синтетический файл, который разойдётся с макетом при следующей сверке, а в
репозитории будет лежать не экспорт.

Другой навык или обёртка, использующие тот же экспортный вызов, сами по себе не устраняют его ограничения. Проверяй фактический файл.

## Порядок работы

1. `get_metadata` **без `nodeId`** — список страниц документа. Их обычно немного, и сразу видно, куда идти.
2. `get_metadata` по нужной странице — уйдёт в файл, дальше греп.
3. Нашёл кандидата — `get_screenshot` по ноде, чтобы убедиться глазами. Дёшево и решает спор.
4. Нода пришла извне (из чата, из таблицы вопросов) — сначала резолвить предков, потом смотреть.
5. Инстанс внутри уже найденного объекта пришёл без внутренностей (это не нода из шага 4) — запроси составной id `I<инстанс>;<узел>` из выдачи родителя.
6. Нужны цифры (отступы, посадка текста, размер декора) — экспорт `download_assets` с `defaultScale` 3–4 и замер по пикселям; для прода — исходник из `rawImages`.
7. Нужны стрелки на канвасе или прозрачный PNG 2×, недоступные через подключённый MCP, — опциональный `peekaboo-control` по разделам выше; при его отсутствии сохрани ручной путь.
8. Нужны комментарии — прочитай полную ветку и ответы по разделу «Комментарии», сверь контекст на макете; готовые материалы используй без повторного UI-чтения.

## Чего не делать

- **Не заявлять «в макетах не покрыто»** на основании дерева узлов. Формулировать как «в дереве не видно, надо посмотреть на канвасе».
- **Не считать пришедшую ноду экраном.** Проверить, не подложка ли это.
- **Не звать `get_design_context` для разведки.** Дорого и обрежется.
- **Не мерить доли пикселя по уменьшенному или натуральному скриншоту.** Для точного замера нужен проверенный масштабный экспорт.
- **Не брать положение декора из дерева.** У повёрнутого узла `x`/`y` — не угол картинки.
- **Не считать `download_assets` гарантией прозрачности.** В проверенном пути фон канваса запекался; проверяй альфу в самом файле.
- **Не писать выводы в общие документы**, пока не подтвердил скриншотом или у человека. Правка чужой доки на основании неполного чтения обходится дороже, чем лишний вопрос.

## Чек-лист

- [ ] Нода из внешнего источника — предки проверены, это фрейм экрана, а не слой
- [ ] Поиск шёл по тексту, по именам фреймов и по номерам нод из репозитория; пустой поиск по фразе не выдан за «нет в макете»
- [ ] Цифры для ТЗ сняты с экспорта `defaultScale ≥ 3` (прод — с исходника из `rawImages`), а не с `get_screenshot`
- [ ] Декор и повёрнутые узлы измерены по экспорту, а не по координатам дерева
- [ ] Греп учитывает экранированные кавычки
- [ ] Вывод про наличие или отсутствие перехода не сделан по метаданным
- [ ] Спорное подтверждено скриншотом или человеком с открытым файлом
- [ ] Экспорт ассета: альфа проверена в файле, а не предположена по формату
- [ ] Peekaboo использован только для стрелок на канвасе, прозрачного экспорта 2× или чтения комментариев; обычное чтение осталось в Figma MCP, отсутствие зависимости не сделало установку обязательной
- [ ] Для UI-экспорта проверены точная нода, размеры 2×, реальная прозрачность и соответствие изображения; изменения собственного UI-состояния восстановлены без перезаписи новых действий пользователя
- [ ] Комментарии: прочитаны исходная реплика и ответы, указаны авторы/время и подтверждённый контекст pin; предложения не выданы за утверждённые требования, обсуждение не изменено
