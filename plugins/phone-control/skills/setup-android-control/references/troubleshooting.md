# Диагностика по ошибке

| Симптом | Следующее действие |
|---|---|
| `Neither ANDROID_HOME nor ANDROID_SDK_ROOT` | Найди установленный SDK, проверь `platform-tools/adb`, передай абсолютный ANDROID_HOME именно процессу MCP. Если оба env заданы, они должны указывать на один SDK. Reload и повторный discovery подключённым tool. |
| Нет Java/JAVA_HOME | Найди установленный совместимый JDK (`/usr/libexec/java_home -V`), проверь его `bin/java -version`, задай JAVA_HOME в MCP. Не меняй Gradle проекта ради Appium. |
| `unauthorized` | Телефон виден, но доверие не подтверждено. **На Android** разблокировать → Настройки → Параметры разработчика → Отладка по USB; выключить/включить, переподключить кабель, подтвердить RSA-запрос для своего Mac. Если меню скрыто: Сведения о телефоне → Сведения о ПО → Номер сборки, семь нажатий. Не отзывать все разрешения без необходимости: это сбрасывает доверие остальным компьютерам. |
| Нет диалога доверия | Проверить разблокировку и USB-отладку на телефоне; можно выполнить `adb -s "$ANDROID_TASK_SERIAL" reconnect`. «USB для зарядки» не доказывает невозможность ADB; MTP не является универсальным требованием. Не повторять reconnect бесконечно. |
| `offline` или устройство отсутствует | Проверить data-кабель, разъём/хаб и состояние телефона; сверить `adb devices -l`. Не выбирать эмулятор вместо физического телефона. Общий `adb kill-server` затрагивает чужие сессии; сначала точечная диагностика. |
| `Operation not permitted`, USB interface error из shell | Возможна песочница Mac: проверить ту же безопасную команду разрешённым способом вне неё. Не менять драйверы/права телефона на основании sandbox-ошибки. |
| `INSTALL_FAILED_USER_RESTRICTED`, Auto Blocker/MDM | Зафиксировать точную ошибку и видимый диалог. Изменение защитной настройки согласовать; не обходить корпоративную политику. |
| APK: signature mismatch, ABI/minSdk | Проверить APK и установленный пакет. Не удалять существующее приложение/данные ради установки. Получить совместимую сборку либо отдельное решение пользователя. |
| Instrumentation/UiAutomator2 timeout | Проверить ADB, разблокировку, отсутствие другого контроллера и конкретный driver log. Сначала свежий экран; не слепой повтор последнего действия и не автоматическая переустановка всего MCP. Удалять/пересоздавать только свою подтверждённо мёртвую сессию, один цикл; повторная ошибка требует диагностики. |
| Экран гаснет при зарядке | Проверь «Не выключать экран» и фактическое питание по разделу «Экран во время зарядки» в setup.md. Ненулевой stay_on_while_plugged_in ещё не доказывает действие для текущего источника. Не подменяй настройку увеличением тайм-аута на батарее. |
| SDK/JDK были на внешнем диске | Проверить, смонтирован ли том и доступны ли фактические пути процессу MCP. Не восстанавливать старый backup поверх нового переноса. |

После исправления повтори discovery, создание/переиспользование и безопасную приёмку через подключённый MCP. Успешная shell-команда не заменяет результат tool в текущем клиенте.
