# Клавиатура и буфер iOS Simulator

Сохранённые настройки, состояние окна и работающий ввод — три разных результата.

«Проверь» разрешает только чтение; «настрой» — описанные настройки. Установка плагина ничего не меняет. Нужны установленный Xcode и iOS runtime; сборка приложений, установка SDK и физические iPhone вне области этого навыка.

## Диагностика и настройки

1. Учти профиль машины и инструкции проекта. Определи путь **используемого** Xcode/Simulator по работающему приложению или установленному Xcode. `xcode-select -p` может показывать только Command Line Tools; глобальный selector не меняй. Для внешнего диска сначала проверь ожидаемый mount и доступность Xcode. Для SDK-команд используй выбранный `DEVELOPER_DIR`, без персональных путей в переносимых инструкциях.
2. **До любой записи прочитай [preferences](references/preferences.md)**: проверенный рецепт читает только нужные поля `com.apple.iphonesimulator`, различает отсутствие и Boolean `false`, проверяет типы до мутации. Глобальная настройка не требует выбора устройства.
3. Требуемые глобальные Boolean значения: `ConnectHardwareKeyboard=true`, `PasteboardAutomaticSync=true`. В `DevicePreferences` исправляй только существующие явные `ConnectHardwareKeyboard=false`; `true`, отсутствующие ключи и остальные поля сохраняй. Не заменяй домен шаблоном и не редактируй plist напрямую.
4. Работающий Simulator может перезаписать preferences из памяти. Перед записью выбери безопасный штатный lifecycle по reference. Завершение Simulator или закрытие окна может остановить устройства — учитывай настройки приложения и действующую авторизацию, объясни последствия. Без разрешения не закрывай рабочие окна, не завершай процессы и не перезагружай устройства.

## Применение к окну

**REQUIRED SUB-SKILL:** перед UI используй `peekaboo-control`, обнаружь актуальные схемы, подключение и права. Не обходи отказ политики CLI-командой.

Получи свежую цель: приложение/PID и конкретное окно/устройство, согласованное с пользователем. Несколько окон не дают права выбрать случайное. Проверь:

| Меню | Требуемое состояние |
| --- | --- |
| I/O → Keyboard → Connect Hardware Keyboard | включено |
| I/O → Input → Send Keyboard Input to Device | включено для выбранной цели |
| Edit → Automatically Sync Pasteboard | включено |

Меняй только **подтверждённо выключенное**, затем наблюдай заново. `enabled` означает доступность действия, а отсутствие галочки в выводе не означает `false`. Наблюдавшийся Peekaboo 4.9.7 `menu list` не выдаёт checked-state; даже window ID не доказывает привязку меню к окну (активным может быть Settings). Нужна отдельная проверка текущего окна и визуально открытого меню; если инструмент этого не позволяет, попроси пользователя выбрать нужное окно и проверить галочки вручную. При отсутствии Peekaboo дай эти же точные ручные шаги, оставив UI-проверку незавершённой. Не устанавливай его автоматически.

`Toggle Software Keyboard` / `⌘K` меняет видимость экранной клавиатуры: скрывать её и менять раскладку не требуется. `Send Keyboard Input to Device` не объявляй глобально сохранённым без отдельного доказательства области действия и сохранности.

## Функциональная проверка и отчёт

В безопасном поле без пароля, отправки формы и автосохранения пользовательских данных проверь набор несекретного контрольного текста **клавиатурой Mac**, затем `⌘V`. Успешный tool dispatch или вставка через targeted paste не доказывают работу физической клавиатуры/`⌘V`.

Для диагностики буфера читай **только перечень форматов** через проверенный metadata/status либо JXA:

```sh
osascript -l JavaScript -e 'ObjC.import("AppKit"); console.log(JSON.stringify({types: ObjC.deepUnwrap($.NSPasteboard.generalPasteboard.types)}));'
```

Отказ доступа или `nil` не доказывает пустой буфер: отметь невозможность диагностики. Не используй `pbpaste` для просмотра содержимого. Пустой буфер или только PNG/TIFF без текста — не поломка синхронизации. Контрольный текст копирует пользователь либо разрешённый transactional temporary clipboard: восстановление только пока тест владеет записью, без затирания более новой копии. Исходный буфер не печатай и не сохраняй в отчёт.

Если текст есть, но `⌘V` не работает, отдельно проверь фокус, передачу клавиш и вставку внутри iOS. Проверь и обратный путь: контрольный текст из Simulator в безопасное поле Mac. По одному симптому не объявляй баг версии Xcode.

Отчёт раздельно: **сохранено** (глобальные значения/отсутствие конфликтов), **применено в выбранном окне**, **набор**, **Mac → iOS**, **iOS → Mac**, **после разрешённого перезапуска**, **наследование устройством без ключа**. Для каждого — проверено/заблокировано/не проверено и доказательство. Без последних двух проверок не обещай сохранность после перезапуска или настройку всех устройств. Не сбрасывай настройки, устройства, приложения, сессии, clipboard-службы и разрешения macOS.
